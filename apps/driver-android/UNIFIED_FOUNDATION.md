# 통합 Android 앱 기반 — G1

2026-10-27. 업턴랩스가 출시할 하나의 STIZ 앱을 위한 **개발 기반**이다. 스토어 제출·실제 로그인·기기 설치·위치 공유를 실행하지 않았다. 서명된 출시 앱이 아니다.

## 구현 범위

- 기본 진입은 공식 origin의 `/store-app`이다. 웹이 로그인과 관리자·선생님·학부모·기사님 역할을 판별한다. 일반 업무 화면은 같은 origin 안에서 이동한다.
- 로그인 기사 경로 `/staff/run`은 아직 지원하지 않는다. 해당 경로는 앱에서 명확한 준비 안내와 함께 차단하고 셔틀 조회 화면으로 돌아간다. `/staff/run`의 계정 권한을 공개 운행 토큰으로 바꿔 우회하지 않는다. 기존 기사 전용 링크 시험 모드만 유지하며, 통합 로그인 운행은 G3의 계정 결합 운행 인증이 필요하다.
- 일반 페이지 허용(`trustedAppPage`)과 위치 기능 허용(`trusted`)을 분리했다. 위치 메시지는 정확한 공식 origin, 최상위 프레임, `/driver/<token>`에서만 처리한다. API·관리자·로그인·임의 외부 페이지에서는 위치 수집을 시작할 수 없다.
- 기존 Android 위치 서비스·명시적 동의·정확 위치/알림 권한·암호화 저장·서버 종료 확인을 재사용한다. 새 권한은 추가하지 않았다.
- 운행 중 다른 역할·다른 운행·로그아웃 화면으로 이동하거나 뒤로 가면 종료 확인을 거친다. 기기의 위치 수집 중단만으로 화면을 넘기지 않고 서버의 실제 `stopped` 응답을 기다린다. 종료 미확인은 기존 운행 화면에 남는다.
- T맵·전화는 명시적인 사용자 조작으로 열며 위치 서비스는 유지한다. 임의 `intent:`, 파일·HTTP·SSL 오류는 거부한다. 앱을 배경으로 보내거나 Activity가 종료돼도 서비스 자체는 임의 종료하지 않는다.
- 통합 모드는 document-start 탐색 관찰자를 사용해 Next.js의 pushState·replaceState·뒤로가기도 확인한다. 별도의 탐색 메시지는 경로만 전달하며 위치 조회·시작·종료 권한이 없다. 관찰 기능을 지원하지 않는 WebView에서는 업데이트를 안내한다.
- Android 13 이상 뒤로가기와 이전 버전 뒤로가기를 함께 처리한다. 일반 뒤로가기는 새 URL을 반복 추가하지 않고 기존 WebView 이력을 사용한다.

## 빌드 모드와 신원

| 모드 | 설정 | 시작 | 개발 패키지 |
|---|---|---|---|
| 통합 기반 기본값 | `stizUnified=true` | `/store-app` | `kr.stiz.driver.unified` |
| 기존 기사 기기 시험 | `stizDeviceTest=true` | 기존 운행 링크 입력/복원 | `kr.stiz.driver.devicetest` |
| 명시적 기사 모드 | `stizUnified=false` | 기존 운행 링크 입력/복원 | 기존 패키지 유지 |

`release`의 기존 `kr.stiz.driver` 값은 임의로 바꾸지 않았다. **최종 출시 패키지명이 확정됐다는 뜻이 아니다.** 새 서명·지문·스토어 등록을 생성하지 않는다. 기기 시험 옵션은 기본 기사 모드를 유지하며 `stizUnified=true`를 명시했을 때만 통합 흐름을 시험한다.

```powershell
# 설치 없이 빌드만 한다. SDK 라이선스를 자동 승인하지 않는다.
./gradlew.bat --no-daemon :app:assembleDebug :app:assembleRelease :app:assembleDebugAndroidTest :app:lintDebug
```

기존 debug 전용 localhost CA 생성과 production release 분리는 유지한다. release origin은 언제나 `https://www.stiz-dasan.kr`이며 debug CA가 포함되면 검증 실패다.

## 아직 완료되지 않은 인증: G3 필수

이 기반은 동일 WebView의 이메일·비밀번호 로그인 흐름을 허용한다. 실제 계정으로 로그인 시험한 결과를 의미하지 않는다.

Google·Apple OAuth를 embedded WebView에서 진행하지 않는다. 시스템 브라우저는 WebView와 로그인 쿠키를 공유하지 않으므로 브라우저를 열었다는 이유로 앱 로그인 성공으로 표시하지 않는다. `/auth/oauth/*`, `/auth/native/*`, 외부 인증 팝업은 준비 안내로 차단한다. 안내에서 브라우저로 별도 사이트를 이용할 수 있지만 앱의 세션과는 별개다.

출시 전 G3 계약:

1. 앱이 임의 nonce·PKCE verifier를 만들고 서버에 challenge를 등록한다.
2. 시스템 브라우저/Custom Tabs에서 OAuth를 완료한다.
3. 서버가 로그인 계정·요청 nonce에 묶인 짧은 일회용 code를 발급한다.
4. 최종 패키지·서명과 연결된 검증 HTTPS App Link로 앱에 돌아온다.
5. 앱이 PKCE verifier로 code를 1회 소비한다. 서버 완료 경로가 WebView의 HttpOnly 세션 쿠키를 설정한다.
6. 취소·만료·재사용·다른 앱/계정·바뀐 state를 거부하고 원래 화면으로 복귀한다.

별도 서버 endpoint와 원자적인 일회용 저장소가 필요하다. 원격 브라우저 쿠키 복사, JWT를 JavaScript나 URL에 넣는 우회는 사용하지 않는다. 본인인증·결제 앱 전환도 최종 통합 패키지에서 별도 검증해야 한다.

## 출시 전 보류

2026-10-28 후속: 사진·문서 chooser와 기본 비활성화 개발용 인증 인계를 로컬 구현했다. 아래 미구현 표기는 첫 기반 시점 기록이며 최신 범위와 실기기 미검증은 `MEDIA_AUTH_FOLLOWUP.md`를 기준으로 한다. release 간편로그인·최종 HTTPS App Links·서명·운영 활성화는 여전히 보류다.

- G3 인증 handoff와 계정에 결합된 기사 운행 시작·로그아웃/역할 회수 연계, 본인인증·결제 앱 전환의 실제 통합 앱 검증.
- WebView 파일 선택(`onShowFileChooser`)과 네이티브 푸시 연결은 아직 구현하지 않았다. 따라서 선생님 사진 업로드·기본 브라우저 밖의 알림/딥링크도 출시 전 별도 구현·검증해야 한다. 웹 화면이 표시된다는 사실로 이 기능들이 동작한다고 간주하지 않는다.
- 최종 패키지·서명·assetlinks 검증, 실제 Android 휴대폰의 잠금/지도/통신 장애·회전·키보드·종료 시험.
- 운영 위치 기능 활성화 및 승인된 실제 접수 대조. 기존 태블릿 단기 시험을 이 새 앱의 실기기 통과로 옮겨 적지 않는다.
- 서명된 AAB·스토어 제출·공개 배포. unsigned release APK는 제출 가능 결과물이 아니다.

검증 실행 결과는 `VALIDATION.md`의 G1 절과 로컬 빌드 로그를 기준으로 한다.
