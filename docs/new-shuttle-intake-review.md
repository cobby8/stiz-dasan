# 신규 셔틀 신청·기사 검토

## 범위와 실제 운영 경계

2026-11-03 사용자 승인으로 로컬 구현·격리 검증한다. 기존 개시일·복귀일·셔틀 상태 커밋의 운영 반영과 구분한다. 신규 검토 기록표는 운영에 만들지 않았으며, 기사 지정·배차 저장·청구·알림도 실행하지 않았다.

## 업무 흐름

1. 관리자가 `/admin/shuttle/intake`에서 적용 월의 승인된 셔틀 신청과 실제 배차 진행 상태를 확인한다.
2. 현재 기사 역할이 있는 계정을 지정하고 명시적으로 검토 요청한다. 신청 승인이나 목록 조회만으로 지정·발송하지 않는다.
3. 지정된 기사는 로그인한 `/staff/shuttle/intake`에서 본인 요청만 확인한다. 승하차 위치·요일·희망 시각을 보고 가능한 등하원 시각 또는 추가 확인 사유를 제출한다.
4. 관리자는 기사 의견을 보고 기존 셔틀 명단·배차 화면으로 이동해 최종 확정한다. 기사 의견은 확정 배차나 학부모 안내 완료가 아니다.
5. 공용 운행 토큰에는 신규 신청 정보를 추가하지 않는다. 선생님·학부모·다른 기사에게는 요청과 위치를 공개하지 않는다.

## 정합성과 실패 처리

- 검토는 신청·학생·적용 월·담당 기사·요청 당시 자료의 지문에 연결한다. 날짜·반·위치·요청 자료가 바뀌면 이전 검토를 현재 확인으로 재사용하지 않는다.
- 관리자의 중복 클릭은 현재 `PENDING`만 재사용한다. 이미 의견을 제출한 건을 다시 검토시키면 이전 건을 `SUPERSEDED`로 보존하고 새 요청을 만든다.
- 서버가 현재 DB 자료로 지문을 다시 계산한다. 클라이언트가 보낸 지문이나 학생 ID만 믿고 저장하지 않는다.
- 요청 지정과 의견 제출은 트랜잭션·잠금 아래 처리한다. 화면 조회는 읽기 전용이며 표를 자동 생성하지 않는다.
- 월별 목록은 50건씩 더 보기를 제공한다. 늦게 도착한 이전 월 응답·중복 항목을 차단하며 조회/제출 실패 시 작성 중인 의견은 보존한다.
- 조회 오류를 빈 목록으로 표시하지 않는다. 검토표가 아직 없으면 준비 미완료 오류로 안전하게 중단한다.

## 별도 운영 승인이 필요한 구조

`20261103130000_enrollment_shuttle_review`는 새 기록표 1개, 색인 3개(현재 요청 중복 방지용 부분 유일 색인 포함), 참조 4개와 값 제약을 준비한다. RLS를 켜고 `PUBLIC`·`anon`·`authenticated` 직접 접근을 차단한다. 서버의 계정 권한 검사로만 사용한다.

`scripts/shuttle-review-db-preflight.mjs`는 수동 읽기 전용 확인 도구다. 이번 기존 기능 배포의 빌드 명령에는 추가하지 않았다. 새 표·기능의 운영 적용은 검증 결과와 범위를 확인받은 뒤 별도로 진행한다.

## 검증

실제 서비스 호출·API 권한·화면 행동 검사, 전용 loopback PostgreSQL 통합과 320/360px 합성 React 화면을 사용한다. 운영 학생을 지정하거나 실제 배차·발송하는 시험은 하지 않는다. 구체적인 결과는 `.Codex/scratchpad.md`와 Git 제외 `.tmp/shuttle-intake-ui-proof/`, `.tmp/shuttle-review-pg-*/evidence.json`에 기록한다.

- 서비스 19/19, UI 행동 14/14, 셔틀 상태 36/36을 독립 재실행해 69/69 통과했다. 별도 API 본문·권한 안내 14/14, TypeScript·Prisma·새 파일 ESLint·diff 검사도 통과했다.
- 실제 격리 PostgreSQL 11/11: 현재 요청 유일성, 재요청 이력, A→B→A 변경 무효화, 역할 회수, 51건 두 페이지 조회, 외부 역할 직접 접근 차단을 확인했다. DB·임시 암호를 정리했다.
- 최종 제품 소스 988개와 별도 생산 빌드 복사본이 모두 일치하며 `npm run build`가 통과했다. 운영 환경파일을 쓰지 않고 접속 불가능한 loopback DB 주소로 검증했다.
- 320/360px 합성 실제 React 화면은 가로 넘침 없이 입력 17px, 조작 영역 약47px을 유지했다. 실제 휴대폰 설치 검증과는 구분한다.
- 전체 `npm test`: 학생 병합 가드 5/5, 일반 2,900건 중 2,897건 통과. 기존 main에도 존재하던 유니폼 관련 3건 실패는 이번 변경과 분리했으며 검사 기준을 완화하지 않았다.
