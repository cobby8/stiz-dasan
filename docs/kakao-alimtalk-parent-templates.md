# 카카오 알림톡 — 학부모 안내 템플릿 1차 9종 (심사 등록용)

> 2026-11-09 작성. 원장 승인(d-phase1): **지금 문구 그대로 + 머리말만 [스티즈농구교실] 로 통일**, 수강신청서 안내의 다비치 제휴 할인 문장은 뺌.
> **본문은 코드(src/lib/messaging/parent-alimtalk-templates.ts 의 PARENT_ALIMTALK_TEMPLATES)와 글자 하나까지 같아야** 한다.
> 알림톡은 등록한 문구와 다르면 발송이 실패한다. 문구를 바꾸려면 코드·이 문서·카카오 템플릿을 **같이** 고치고 재심사를 받는다
> (테스트 tests/parent-alimtalk-templates.test.mjs 가 이 문서와 코드 틀이 같은지 검사한다).
> 체육관 대관 6종은 따로 있다: docs/kakao-alimtalk-rental-templates.md

## 공통

- 유형: **기본형 · 정보성**(이미 체험·수강·특강을 신청했거나 셔틀을 이용하는 학부모에게 보내는 처리 결과 안내). 광고 문구·혜택 홍보·이벤트 문구 없음.
- 강조 표기·이미지: 사용 안 함.
- 솔라피 «대체 발송(문자)»: **사용 안 함** 으로 등록한다. 알림톡이 실패하면 우리 코드가 같은 본문을 문자로 대신 보낸다(이중 발송 방지).
- 템플릿 id 를 받으면 아래 «환경변수»에 넣는다(Vercel). 비어 있으면 그 안내는 지금처럼 **문자(SMS/LMS)** 로만 나간다.
- /admin/sms «자동 발송» 에서 해당 규칙의 기본 채널을 «알림톡(실패 시 문자)» 로 바꿔야 알림톡이 나간다. 순서는 상관없다
  (id 만 있고 규칙이 문자면 문자, 규칙만 알림톡이고 id 가 없으면 문자로 대체 — 어느 쪽이든 학부모는 받는다).
- 이 9종의 문구는 /admin/sms 문구 화면에서 **잠겨** 있다(«카톡 등록 문구라 수정하려면 재심사 필요» 안내). 켜기/끄기만 된다.

### 검수자 의견(심사 요청 시 «검수자에게 보내는 의견» 칸에 붙여 넣기)

```
스티즈농구교실(남양주 다산 어린이 농구교실)이 수업을 신청·이용 중인 학부모님께 보내는 정보성 안내입니다.
체험수업 일정 확정, 수강신청서 작성 링크, 셔틀 탑승·미탑승, 방학특강 신청 처리 결과와 결제 요청처럼
학부모님의 신청·이용으로 생긴 내용만 담았고, 할인·이벤트 등 광고 문구는 넣지 않았습니다.
수신 대상은 해당 학생의 보호자 1명이며, 관리자가 처리한 즉시 1건씩 발송됩니다.
```

## 2. 수강신청서 안내

- 환경변수: `ALIMTALK_TPL_TRIAL_ENROLL_GUIDE` · 규칙 트리거: `TRIAL_ENROLL_GUIDE_PARENT`
- 보내는 때: 체험수업 후 관리자가 «수강신청서 안내»를 보낼 때
- 카테고리(제안): 서비스이용 › 이용안내(또는 신청접수)
- 변수: `#{학생명}` `#{신청서링크}` `#{학원전화}`
- 버튼: 선택(넣는다면 웹링크 «수강신청서 작성» — 링크는 본문 `#{신청서링크}` 와 같은 값. 버튼을 넣어도 본문 링크는 유지 — 문자 대체 시 같은 본문)
- 바뀐 점: 지금 문자의 «다비치안경 남양주다산점 제휴로 스포츠고글 35,000원, / 안경·고글 구매 시 10% 추가 할인…» 2줄과
  «자세히 보기: …/notices/…»(제휴 홍보 공지) 줄을 뺐다 — 제휴 가격·할인은 광고로 반려된다(원장 결정 d-davichi).
  문자도 같은 틀이라 문자에서도 빠진다. 제휴 안내가 필요하면 신청서 화면에만 둔다.

```
[스티즈농구교실] #{학생명} 수강신청서
아래 링크에서 작성해주세요 :)
#{신청서링크}

■ 수업 준비물: 실내용 운동화, 물 담은 텀블러

■ 안경 착용 안내
안경은 부상 위험이 있어 스포츠고글 착용을 권장합니다.

문의: #{학원전화}
```

## 등록 후 할 일(PM)

1. 승인된 템플릿 id 9개를 Vercel 환경변수(위 `ALIMTALK_TPL_*`)에 넣고 재배포.
2. /admin/sms «자동 발송» 에서 9개 규칙의 기본 채널 = «알림톡», 대체 = «문자» 로 바꾼다. 외부(학부모) 알림톡 채널·대체 문자 채널이 켜져 있는지 확인.
3. 원장 휴대폰으로 트리거별 1건 시험 → `NotificationDelivery.messageType='ALIMTALK'`, `fallbackUsed=false` 확인.

## 설계 메모 — 2차 이후

### 수동 공지용 «카톡 틀 선택» (원장 결정 d-manual · 추천 ② — 이번엔 구조만, 구현은 2차)

- 자유 문구 공지는 알림톡이 안 된다(광고·자유 문구 반려). 그래서 «자주 쓰는 공지»를 **미리 심사받은 틀**로 만들어
  /admin/sms 수동 발송 화면에 «카톡 틀 선택» 드롭다운을 둔다. 틀 종류는 원장에게 받는다.
- 구조: 이 금고(`PARENT_ALIMTALK_TEMPLATES`)에 `kind: "manual"` 틀을 추가 → 화면은 틀을 고르면 변수 입력칸만 보여 주고
  (자유 본문 입력은 막음) 미리보기 = 금고 틀 채운 결과. 발송은 `enqueueManualSmsBatch` 에 `{ templateTrigger, variables }` 를 함께 넘겨
  크론(`api/cron/manual-message-dispatch`)이 `sendMessageDetailed({ audience: "EXTERNAL", alimtalk })` 로 보낸다(장부 `actualChannel` 기록).
- «틀 없이 자유 문구» 는 지금처럼 문자로 남긴다(원장 결정 d-manual).

### 카카오 접수 처리 결과의 «원장 덧붙임 한 줄» (원장 결정 d-kakao-line)

- 결과 안내(customer-notice)는 2차 대상이라 이번엔 코드를 바꾸지 않았다. 2차 전환 때 규칙: 상태별 5종 틀로 나누고,
  **원장이 한 줄을 덧붙인 건은 그 건만 문자**로 보낸다(자유 문구는 알림톡 불가). 판정 위치 = `actions/customer-notice.ts` 발송부
  (`extraLine` 이 비었을 때만 alimtalk 를 넘긴다).

- 인증번호(회원가입·보호자 계정·초대) · 보안 알림(간편로그인 연결·본인인증 로그인) · 카카오채널 링크 안내 — 문자 유지.
