# 체험 일정 저장·목록 표시 검증 (2026-11-02)

## 변경 목적과 승인
사용자가 신청 내용·체험 시간 변경 저장 후 목록의 수업 표기가 잘못된다고 보고했다. 사용자 승인 묶음은 선호 수업 키 정리, 교시 표시 오류 제거, 실제 확정 시각 일치, 이전 날짜 조회 응답 차단과 합성 검증이다. 운영 신청 수정·발송·배포는 실행하지 않는다.

## 확인한 원인과 수정
- 추가반의 `custom-*` 식별번호에서 숫자를 교시로 추출했다. 이제 명시적인 `N교시`나 엄격한 요일-교시 키만 사용한다. 교시가 없는 추가반은 실제 확정 시각을 표시한다.
- 희망 요일·교시 수정 후 이전 정규 수업 키가 남았다. 저장 시 함께 정상화하고 추가반 키와 기존 확정 반·일시는 보존한다. 기존 불일치 신청의 관련 필드 수정에서도 정상화한다.
- 목록·상세가 반 원본 시간이나 짧은 교시 표시로 실제 변경 시각을 누락했다. 목록은 기본 시간과 다를 때 시각을 병기하고, 상세 확정일정에는 실제 시각을 항상 표시한다.
- 서버가 넘긴 Date 객체에 문자열 `.trim()`을 호출해 일정 변경창이 열리지 않았다. 기존 날짜 변환 함수를 사용하도록 고쳤다.
- 취소된 이전 날짜 수업 조회가 뒤늦게 화면을 덮지 않도록 성공 응답에도 취소 확인을 적용했다.

## 검증과 한계
- 신규 회귀 12건: 실제 저장 액션을 메모리 자료에 실행한 뒤 재조회·표시 검사, 실제 목록·짧은 상세 표시 함수 검사, 추가반·수동 시각·기간별 수업 시간·선호 키·Date 객체·취소 응답 검사.
- 전체 테스트 2,778건 및 학생 가드 5건 통과. 별도 검수자가 같은 변경을 독립 검사했다.
- 격리 브라우저에서 실제 React 화면에 합성 Date 객체와 추가반을 제공했다. 변경창 정상 진입 → 실제 키 입력으로 15:00에서 16:00 변경 → 합성 저장 → 목록 `화3 · 16:00` → 상세 `11/10 화3 · 16:00` 확인, 화면 오류 0건.
- 브라우저 합성 저장은 메모리만 변경한다. 운영 저장 액션은 별도 메모리 DB 회귀로 검증했으며 실제 운영 신청을 수정하지 않았다.
- 시험 도구의 time 입력 `fill`은 이 환경에서 React 변경 이벤트를 전달하지 않았다. 화면 값만으로 저장 결과를 판단하지 않고 실제 키 입력 후 결과를 재확인했다.
- 운영 배포 전이므로 운영 사이트에는 이전 표기가 남는다. 푸시·배포·TestFlight·청구·알림은 실행하지 않았다.

## 별도 운영 작업
명시 승인된 휴원생의 11·12월 월·수·금 셔틀 12행만 제외했다. 운영 감사 기록의 전 상태 12행과 현재 해당 ID 잔여 0을 독립 READ ONLY로 확인했다. 원생·수강·출결 이력은 변경하지 않았다. 재개 학생 월·금 17:40 후보는 별도 로컬 운영 원장에 기록했으며, 월요일 앞뒤 운행 충돌 때문에 배차 저장은 보류했다. 개인정보가 있는 원장은 Git에 포함하지 않는다.
