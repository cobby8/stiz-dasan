# 수강신청 재검토와 다중 역할 보호자 연결

2026-10-20. 사용자 승인에 따라 로컬 코드와 합성 자료만 수정·검증한다. 운영 신청 승인·자녀 연결·청구·발송·배포는 실행하지 않는다.

## 작업 그룹

| 그룹 | 담당 | 의존 관계 | 완료 기준 |
|---|---|---|---|
| 승인·재검토 서버 | enrollment_parent_link | 기존 계정·신청 정책 조사 | 명시적 보호자 선택, 역할 유지, 재검토 이력·동시 처리 보호 |
| 관리자 신청 화면 | compact_seasonal_filters | 서버 입출력 계약 | 후보 조회·선택·실패 안내, 별도 재검토 확인, 컴팩트 화면 유지 |

## 동작

- 승인할 보호자 계정을 직접 선택한다. 전화번호는 후보 검색에만 사용하고 후보가 한 명이어도 자동 연결하지 않는다. 이미 신청서에 명시된 연결은 유지하며 승인창에서 바꾸지 않는다.
- 신규 보호자도 별도로 선택해야 한다. 내부 입력값 `__NEW__`와 기존 후보·명시 연결이 모두 없는 조건을 함께 확인한다. 조회 실패나 부적격 계정이 있으면 신규 계정 생성으로 대체하지 않는다.
- 관리자·부관리자·선생님 계정은 단일 Auth 연결 및 해당 Auth 계정의 존재·삭제·차단 상태를 다시 확인한다. 기존 역할을 바꾸지 않고 자녀 관계만 추가한다. 서버 검증은 후보 조회와 승인 시 각각 수행한다.
- 승인 전용 Auth 조회는 5초 뒤 취소한다. 공통 관리자 클라이언트의 기존 호출은 유지하고 선택적인 fetch 주입만 추가했다. 비밀 키·Auth ID·이메일은 후보 응답에 포함하지 않는다.
- 반려되었고 원생 전환이 없는 신청만 사유를 적어 상담 대기로 되돌린다. 이 단계는 학생·수강·청구·알림을 생성하지 않는다. 재검토와 이후 정식 승인은 별도 동작이다.
- 행 잠금과 조건부 변경으로 중복 승인·재검토를 막는다. 같은 연락처의 신규 보호자를 동시에 생성하지 않도록 트랜잭션 잠금을 사용한다.
- 서버 저장 성공 뒤 목록 갱신만 실패하면 저장 완료와 조회 실패를 구분하며 같은 처리를 반복하도록 유도하지 않는다. 통신 실패 시 선택값·메모·사유를 보존한다.
- 수강 시작일 예약 정책은 이번 범위에 포함하지 않는다. 실제 지정 자녀는 정식 원생 등록 전이며, 현재 반 확인과 운영 시작일·실행 승인은 별도로 필요하다.

## 구현 경로

- `src/app/actions/admin.ts`: 관리자 가드, 후보 조회, 승인 입력, 명시 연결 저장, 재검토 액션.
- `src/lib/enrollment/approval-parent.ts`: 후보·Auth 확인, 명시 선택 계약, 동시 처리, 재검토 이력.
- `src/lib/supabase/admin.ts`: 승인 전용 시간 제한을 위한 선택적 fetch 주입.
- `src/app/admin/apply/ApplyAdminClient.tsx`, `ApplyAdminModals.tsx`: 보호자 선택·기존 연결 잠금·재검토 확인·실패 안내.
- 스키마·권한 역할값·기존 계정·운영 데이터는 변경하지 않았다. 자동 청구·발송을 추가하지 않았다.

## 검증과 한계

- 최종 선택 계약 기준 전체 275파일 2,143건 통과. `.tmp/enrollment-link-final/clean-tests-result.json`, `clean-tests.log`. 별도 소스 사본·환경 변수 제한·네트워크 가드로 운영 연결을 차단했다.
- 관련 서버 39건, 독립 관련 검사 30건과 UI 43건, 기존 신청 필터 230건 통과. 중복된 검사를 합산한 총계로 표현하지 않는다. TypeScript·새 helper/관련 UI lint·diff 검사 통과. 기존 저장소 전체 lint가 정리됐다는 뜻은 아니다.
- 독립 실제 PostgreSQL 18건에서 원본 승인 함수와 실제 SQL을 실행했다. 명시적 관리자 연결·역할 유지·중복 승인 1건·보호자/수강 1건·재검토 이력 1건·승인 중 재검토 경합·실패 시 신규 대체 0건을 확인했다. Auth 응답과 외부 원장 hook은 대역이며 실제 Supabase 인증·외부 시스템 쓰기 검증은 아니다.
- 후속 실제 PostgreSQL 8건에서 원래 반려 사유·처리 시각과 재검토 사유를 연락 이력 한 건으로 보존하고, 이후 승인으로 신청 메모가 바뀌어도 반려 이력이 남는 것을 확인했다. 앞선 18건과 겹치므로 고유 검사 26건으로 합산하지 않는다.
- 검색창의 기본 지우기 표시와 별도 지우기 버튼이 겹치던 문제를 두 검색창에 한정해 수정했다. 독립 실제 Chrome 검사 14/14 통과. 관리자 메뉴 압축 높이 경계는 450→500px로 조정했고 독립 77/77 통과했다. 830×453 업무 목록이 181→304px로 늘고 1440×900 PC 배치는 유지됐다.
- 증거 `.tmp/qa-followup/enrollment-parent-pg/{report,cleanup}.json`, `enrollment-parent-ui-final.json`, `.tmp/enrollment-parent-link-browser/`.
- 독립 시험 DB는 중지했고 포트 55462를 반환했다. 해당 중지 임시 폴더의 재귀 삭제는 자동 승인 검토가 차단했으며 다른 도구로 우회하지 않았다. 잔여는 cleanup 기록에 남겼다.
- USB·Android 기기 결과는 [역할 후속 검증](role-followup-verification.md)에 별도로 기록한다. 합성 인증·부모 연결 검증을 운영 계정의 실제 등록 완료로 표현하지 않는다.
