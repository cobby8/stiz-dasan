# 공개 홈페이지 날짜·모집·모바일 이동 전수 점검

## 범위와 작업 그룹

- 사용자 요청: 나머지 공개 페이지의 잘못된 날짜·모집 안내·메뉴 노출을 조사하고 수정하며 모바일 페이지 이동까지 검증한다. 배포하지 않는다.
- 콘텐츠 담당은 홈·공지·갤러리·수강 월·체험 일정 표시, 탐색 담당은 전체 메뉴/이동 매핑, PM은 로그인/가입·뒤로가기·상품 오류 UI와 환경 통합, 독립 QA는 브라우저 재현과 최종 대조를 담당했다. 파일 소유를 분리하고 API·조회·권한·가격·운영 자료는 변경하지 않는다.
- 기존 공개 26개 화면 유형을 기준으로 실제 공지·상품 링크까지 36개 공개 경로를 확인했다. 상세 ID가 다른 공지 4개와 상품 8개를 포함한다. 개인 토큰·역할별 업무 화면은 공개 메뉴 경로와 구분한다.

| 공개 경로 묶음 | 화면 구성·이동 |
|---|---|
| 홈 | 공통 헤더/푸터 직접 사용, 공지·갤러리·프로그램·신청 이동 |
| 학원 소개·프로그램·수업 순서·시간표·수업찾기·연간 일정 | 공통 공개 레이아웃, 프로그램→시간표 필터 query 보존 |
| 공지 목록/상세·갤러리/확대·FAQ·약관·개인정보 | 공통 메뉴·게시일·목록/상세 복귀 |
| 신청 안내·체험·수강·유니폼·특강 목록/상세/신청 | 선택/검토 단계 및 날짜·모집 상태, 실제 제출 제외 |
| SHOP·상품 8개 | 공통 목록 메뉴·상품 자체 SHOP 복귀 헤더, 외부 구매 실행 제외 |
| 로그인·보호자 가입·학부모/선생님 설치 안내 | 별도 진입 구성의 홈/뒤로/로그인·가입 이동, 실제 인증/설치 제외 |

설치 안내의 전체 메뉴 생략과 상품 프레임의 자체 헤더는 기존 목적에 따른 구성이다. 메뉴 누락으로 보고 임의로 전체 메뉴를 추가하지 않았다.

## 재현한 문제와 수정

1. **게시 날짜가 기기·서버 시간대에 따라 달라짐:** 홈·공지·갤러리 표시를 `formatKstDate`로 통일했다. 잘못된 날짜의 `toISOString()` 렌더 중단을 막고 공지 연도를 표시한다. 기존 날짜 저장·조회는 그대로다.
2. **수강 월이 한국 월 경계에 이전 달로 표시됨:** 기존 KST 모듈에 `kstMonthLabels`를 추가해 현재/다음 월 선택을 만든다. 청구나 시작일 계산은 변경하지 않는다.
3. **과거 공지와 현재 모집의 혼동:** 공지 모델에는 만료일·특강 연결이 없어 제목이나 게시일만으로 종료를 추정하지 않았다. 공지 상세에 게시 당시 내용임을 짧게 표시하고 현재 시간표/방학특강 확인 링크를 분리했다. 원문과 외부 폼 링크는 보존한다.
4. **로그인↔가입 시 신청 연결 정보가 사라짐:** 교차 링크와 간편가입 실패 후 휴대폰 전환에서 내부 복귀 경로와 연결 정보만 유지한다. 기존 `isSafeInternalPath`로 외부/우회 주소를 제외하고 이름·연락처·오류·소셜 플래그를 불필요하게 복사하지 않는다. 인증·권한·계정 연결 API는 변경하지 않았다.
5. **모바일 공지 상세 헤더 뒤로가기가 홈으로 이동:** Next App Router 기록에는 기존 감지가 기대한 `idx`가 없었다. 공개 경로에서는 브라우저 Navigation API의 이전 동출처 항목을 읽어 원래 목록으로 돌아간다. 미지원/읽기 실패 시에는 상세별 부모 경로를 사용한다. 기록을 저장/조작하지 않고 업무 역할·설치 앱의 기존 범위 규칙은 유지한다.
6. **체험 날짜·요일·교시 모순:** 과거 날짜 차단, 날짜의 한국 요일 동기화, 해당 요일의 실제 전달된 교시만 표시, 일정 변경 후 잘못된 교시 해제를 적용했다. 시간표가 없으면 임의로 1~8교시를 만들지 않는다. 단계 이동·기존 신청 로드·최종 제출 직전에 같은 UI 검증을 사용한다. 기존 신청의 입력/ID를 보존하며 정정 후 검토로 진행한다. 단계 복귀 뒤 오류 안내가 화면 밖에 숨는 문제도 수정했다. 렌더 완료 후 안내가 보이도록 이동하며 같은 오류의 재시도에도 적용한다. 강제 포커스나 타이머는 사용하지 않는다.
7. **상품 오류 화면 제목에 영구 로딩 표시:** 상품을 열 수 없을 때 헤더와 본문의 상태를 일치시켰다. 상품 조회·가격·신뢰 도메인 검사·외부 프레임은 변경하지 않았다.

## 검증 환경과 근거

- 운영 접속·원본 환경 파일 없이 기존 공개 캡처로 재구성한 별도 PostgreSQL·소스 복사본을 사용한다. 계정·학생은 합성이다. GET/HEAD 프록시와 외부 연결 차단을 유지한다.
- 신청/가입 검토에 필요한 합성 조회·실패 응답은 브라우저에서 정확한 요청만 대체한다. 실제 접수·SMS·인증·결제·외부 상품 주문은 실행하지 않는다.
- 후보 기준: 실제 href 36개 GET 36/36, 320/360px 화면 72/72, 모바일 메뉴 실제 클릭 26/26, 추가 흐름 20/20. 헤더 뒤로가기와 체험 날짜 2건은 별도 실패로 보존하고 수정 후 재검증한다.
- 후보 증거: `.tmp/public-all-pages-audit/candidate-{routes,layout,menu-clicks,flow-results,navigation,trial-date-validation}.json`.
- 최종 자동 검사: `npm test` 학생 보호 가드 5/5·회귀 2,305/2,305, `npx tsc --noEmit` 통과. 콘텐츠/체험 관련 24/24, 이동·기존 뒤로가기 관련 17/17 통과. 기존 정적 검사의 함수 위치 assertion은 helper 추출 구조에 맞춰 바꾸고 실제 slotKey 전송·합성 제출의 항목/값 행동 검증을 유지했다.
- 새 helper·체험·이동 로직의 타입 검사는 통과했다. 기존 공개 컴포넌트의 any/effect/이미지 경고 등 무관한 ESLint 부채는 별도로 유지한다.
- 최종 소스 879개와 시험 복사본이 개별 해시까지 일치한다. 전체 지문 `00bb4fa7cb43ae51e0f4845681da0b512b26b5666adf2172e72c6b157d7d5ab9`, 생산 빌드 종료 0. `.tmp/public-all-pages-audit/pm/source-copy.json`과 `.tmp/sport-public-qa/rebuild-result.json`에 기록했다.
- 최종 독립 브라우저 검사 **92/92**, 실패·JavaScript 오류 0: 36경로 GET, 320/360px 레이아웃 72, 수정 동작 16, 시간표 대조 1, 차단 경계 3. 경로 GET은 72폭 검사에 포함되며 별도로 중복 합산하지 않았다. `.tmp/public-all-pages-audit/final-independent-report.json`과 `final-route-layout.json`이 정본이다.
- 수정 동작에는 로그인/가입·실패 후 전환의 연결 보존, 실제 상세 뒤로가기·미지원 대체, 과거일/요일 일치, 기존 신청 오류 노출·정정·재시도, 상품 오류 제목·공지 안내를 포함한다. 기존 신청 오류 안내는 320px에서 화면 위 347~417px 안에 표시된다. `final-error-visible320.png`를 보존했다.
- 현재 체험 슬롯 31개의 교시·시간을 공개 시간표와 대조해 누락·시간 불일치 0을 확인했다. 최종 브라우저 실제 쓰기 전달·운영 작업·푸시·배포는 모두 0이다. 후보의 메뉴 실제 클릭 26/26·추가 흐름 20/20과 최종 92건은 버전을 구분한다.

## 한계와 운영 경계

- 브라우저 폭 재현이며 실물 휴대폰 검증은 아니다. 실제 운영 인증·신청 접수·설치·외부 서비스 내부 동작을 검증한 것으로 보고하지 않는다.
- 공개 체험 슬롯 API는 Class 기반으로 요일·교시·잔여 인원만 제공한다. UI에 없는 특정 휴강일·운영 유효기간을 추정하지 않는다. 현재 입력의 날짜/요일/교시 일관성과 전달된 마감 상태만 검증한다.
- 운영 DB·실제 발행/발송·결제·푸시·배포는 실행하지 않는다.
