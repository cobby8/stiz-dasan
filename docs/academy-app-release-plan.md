# STIZ 역할 앱 출시 준비 계획

2026-10-19 · 출시 주체: 업턴랩스 · 상태: 설계·검증 준비, 출시 미승인

이 문서는 실제 서비스 코드·운영 DB·스토어를 변경하지 않는 준비 계획이다. 사용자 승인에 따라 역할별 화면 개선과 검증을 먼저 끝내고 출시 가능 여부를 판단한다. 화면 크기 검사 통과나 시험 APK 빌드는 고객 출시 완료를 뜻하지 않는다.

## 일반 앱의 역할·연결 규격

1. 로그인 성공 후 서버의 현재 권한을 읽고 자기 홈으로 진입한다. 사용자가 가입 화면에서 관리자를 선택하여 권한을 얻는 흐름은 만들지 않는다.
2. 전환 메뉴는 실제 허용된 화면만 표시한다. 예를 들어 본인 자녀가 있는 선생님은 학부모 화면을 열 수 있지만 다른 가족 자료는 보지 못한다. 관리자/선생님 이동도 서버 허용 범위와 일치해야 한다.
3. 권한 변경·계정 교체·로그아웃 때 이전 학생 화면·기기 알림 연결·메모리를 정리한다. 진행 중 출결·작성 내용은 저장 확인 또는 명시적 취소 없이 잃지 않도록 한다.
4. 브라우저 로그인 왕복은 앱에서 시작한 요청과 일치하는지 검증하고 만료·취소·재실행을 처리한다. 다른 주소·다른 계정의 응답으로 복귀하지 않는다. 소셜 로그인 제공자의 실제 앱 로그인 지원과 Apple 로그인 정책 적용 여부를 출시 시 확인한다.
5. 현장 농구 수업·셔틀 대금은 물리적 서비스 결제 기준으로 기존 PG 연결을 검토한다. 앱 안 디지털 강의·유료 기능을 판매하면 별도 인앱 결제 정책을 검토한다. 결제 앱으로 이동한 뒤 취소·실패·중복 탭·앱 재실행에도 서버 확인 결과로만 납부 완료를 표시한다. 이번 검증에서는 실제 과금하지 않는다.
6. 사진·파일·전화·지도는 필요한 기능에서만 권한/외부 앱을 요청한다. 거부·미설치 시 되돌아갈 방법을 제공한다. 일반 앱은 기사 위치 수집 권한을 요구하지 않는 구성을 기준으로 한다.
7. FCM/APNs 알림은 기기 등록·권한 거부·토큰 갱신·로그아웃·공유 기기 계정 변경을 검증한다. 알림 클릭은 서버 권한을 다시 확인하고 허용 화면으로 이동한다. 공개 잠금 화면에 학생 민감정보가 노출되지 않는 기본 문구를 정한다.
8. 탈퇴는 재인증·영향 안내·보관 예외·요청 접수/완료를 구분한다. 단순 로그아웃을 탈퇴 완료로 표시하지 않는다. 요청 URL과 지원 연락처를 스토어에 제출할 수 있게 준비한다.

## 기사 앱의 별도 기준

- 명시적 운행 시작·위치 고지·권한 허용 후 수집하고 종료 시 중단한다. 강제 종료·재부팅 뒤 몰래 재시작하지 않는다.
- 운행 링크·운행 자격은 일반 회원 로그인과 별개임을 유지한다. 한 차량·한 활성 기기 정책, 만료·재사용·링크 폐기·동시 시작 검사를 통과해야 한다.
- 화면 복귀·종료 미확인·통신 실패·오래된 좌표를 성공으로 숨기지 않는다. 실제 관리자/학부모 표시는 권한 있는 승인 시험 범위에서 대조한다.
- Android 권한 이름과 Play의 심사 판단은 같지 않다. 현재 `ACCESS_BACKGROUND_LOCATION` 선언이 없어도 실제 화면 밖 위치 이용 방식에 맞는 고지·서비스 신고·심사 자료를 준비한다.
- `location` 포그라운드 서비스의 사용 목적·사용자가 시작하는 과정·중단 시 운행에 미치는 영향·종료 방법을 설명하고 실제 시연 영상을 준비한다. 권한 명칭만으로 심사 면제를 판단하지 않는다.
- 새 운영 테이블·기능 설정은 미적용 상태다. 적용 대상·중단 방법·보관/삭제 기준을 제시하고 실행 직전 승인을 받는다.

아래는 통과 결과가 아닌 실행 계획이다. 모델·OS·브라우저/WebView·실제 CSS 표시 크기·앱 버전을 시험 때 기록한다. 기기 물리 해상도를 CSS 표시 크기로 잘못 기록하지 않는다.

합격 기준은 페이지 전체 가로 넘침·글자 잘림·고아 버튼·기능을 밀어내는 중복 행이 없고, 작은 터치 화면의 버튼 영역 44 CSS px 이상과 정상 스크롤을 유지하는 것이다. 표는 필요한 경우 표 안에서만 가로 이동한다. 회전 전후 검색·출결·상세창 상태와 저장/전달 결과가 유지되어야 한다. 확대 접근성은 모든 화면을 같은 높이로 압축하는 것보다 내용·조작 보존을 우선한다.

기사 위치는 정상 수신 구간에서 서버 접수 간격 30초 이내를 시험 목표로 삼는다. 좌표 추정 정확도와 실제 거리 오차는 구분한다. 목표 미달 구간·배터리 소모·원인을 기록하고 무조건 연속 작동한다고 홍보하지 않는다.

## 업턴랩스·서명·심사 자료

- Play Console과 Apple Developer/App Store Connect의 실제 등록 상태·조직명·결제/계약·게시 권한을 사용자가 확인한다. 자격 증명을 대화에 보내도록 요청하지 않는다.
- Google 조직 계정은 D-U-N-S와 조직 신원 확인 요건을 확인한다. Apple 조직 등록은 법적 실체·D-U-N-S·계약 권한·조직 도메인 이메일·공개 웹사이트를 확인한다. 업턴랩스 상호만으로 법인 등록이나 판매자 표시가 확정됐다고 간주하지 않는다.
- 서명키·키 암호·APNs/FCM 자격·개발자 인증서는 안전한 로컬 저장소 또는 승인된 비밀 저장소로 관리한다. Git·문서·Issue·빌드 로그에 비밀값/파일을 넣지 않는다. 최소 권한과 접근 소유자를 정하고 복구 수단을 확보한다.
- 심사용 계정은 합성 학생·합성 보호자·가짜 청구와 시험 운행 자료만 사용한다. 심사자가 직접 로그인·역할 화면·위치 고지/종료를 재현할 수 있게 안내한다. 비밀번호·실제 운행 링크는 공개 문서에 쓰지 않는다.
- 개인정보처리방침·지원·계정 삭제 요청 URL, 데이터 수집/공유/보관·암호화 설명, 위치 기능 시연 자료를 실제 동작과 맞춘다. 사용 대상이 보호자/성인 직원이라는 사실과 아동 자료 처리도 정확히 신고한다.
- 일반 앱이 웹 화면을 보여준다는 이유만으로 스토어 적합성을 단정하지 않는다. 실제 학원 업무 가치·네이티브 연결·완결된 로그인/권한 흐름과 Apple 최소 기능·디자인 기준을 검토한다.
- 제출 직전에 당시 정책·SDK 조건을 다시 확인한다. 현재 미결을 임의로 “준수 완료”로 표시하지 않는다.
