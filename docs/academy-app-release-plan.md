# STIZ 통합 앱 출시 준비 계획

최초 작성: 2026-10-19 · 최신 정정: 2026-10-28 · 출시 주체: 업턴랩스

**현재 기준은 STIZ 앱 하나**다. 10월 19일의 ‘일반 앱+별도 기사 앱’ 권고는 10월 25일 사용자 결정과 10월 27~28일 통합 앱 구현으로 대체했다. 과거 시안·웹·태블릿 시험은 당시 증거로 보존하며 최신 네이티브 실기기 통과로 합산하지 않는다. 문서·로컬 점검에 이어 격리 합성 환경 구성도 승인받았으며 운영 배포·TestFlight 업로드는 하지 않는다.

## 확정 기준과 미결

후속 사용자 승인으로 [격리 HTTPS 환경](native-device-sandbox.md)을 구성했다. Android 개발 APK·서버 검증은 완료했고 iOS는 개발 연결 코드·정적 검증까지만 완료했다. 아래 B의 설계·로컬 구현은 진행됐지만 신규 iOS 컴파일·양쪽 실기기 검증·실제 인증 계약은 미완료다. 기존 A 승인에 자동으로 외부 실행 권한이 추가된 것은 아니다.

| 구분 | 기준 |
|---|---|
| 앱 구성 | 한 앱에서 서버가 허용한 역할 화면 진입·전환. 관리자·선생님·학부모 다중 역할 허용, 임의 권한 부여 없음 |
| 플랫폼 | 학부모·선생님·관리자 iOS/Android, 기사님 Android. 현재 차량 1대 |
| 화면 | 현재 홈페이지와 맞춘 스포츠 스타일·공식 로고, 중복 카드/행·불필요한 여백 축소. 10월 19일 라벤더 시안은 과거 단계이며 재적용 지시가 아님 |
| 구현 | Android `apps/driver-android` WebView+위치 서비스, iOS `apps/stiz-ios` UIKit/WKWebView. TWA/PWABuilder 새 생성 아님 |
| 식별자 | 기본 Android debug `kr.stiz.driver.unified`, 격리 APK `kr.stiz.driver.sandbox`, iOS `kr.stiz.academy.dev`. 정식 ID·서명·팀·스토어 소유 미결 |
| 이번 승인 | 문서·시험표·로컬 점검 및 후속 격리 합성 환경·개발 앱 연결. 실제 서비스 기능·계정·정식 서명·운영 환경·고객 자료 변경 없음 |

## 역할별 실제 기기 시험 기준

아래는 통과 결과가 아닌 실행 계획이다. 모델·OS·WebView·CSS 표시 폭·앱 버전/해시·합성 데이터 버전·시각·증거를 기록한다. 물리 해상도와 CSS 폭을 구분하고 기기 연결은 시험 직전 확인한다.

| 역할 | 핵심 흐름 | 실패/복귀 포함 |
|---|---|---|
| 학부모 | 로그인→본인 자녀→수업/납부→변경 신청→가족 연결→탈퇴 | 자녀 없음·오연결·요청 취소·망 실패·결제 취소·키보드/버튼·로그아웃 후 이전 자료 거절 |
| 선생님 | 수업→출결→학생별 수강료/납부→청구 보기→사진/음성→수업 종료 | 긴 이름·미청구·첨부 취소/복수·권한 거부·미저장 이동·종료 실패·권한 회수 |
| 관리자 | 메뉴→신청/필터→등록/부모→이월/보강→청구 검토→배차→역할 전환 | 좁은 폭·필터 중복·원장 미확정 차단·중복 발행 방지·저장재조회·권한 외 URL 거절 |
| 기사(Android) | 운행 권한/공개 링크 구분→시작→다음 정류장→전화/지도→탑승→종료 | 잠금/T맵 각 20분·전화·실외·절전·망 단절/복구·복귀·동시 기기·종료 후 추가 수신 없음 |

| 기기/표시 | 검사 |
|---|---|
| Android 360px, 기사 320px 추가 | 글씨·탑승 버튼을 줄이지 않고 긴 정류장·전화·시각·길안내 배치, 가로 넘침·끝 한 글자 고립 줄바꿈 |
| Android 일반/폴더블·태블릿 | 회전·접힘/펼침·분할·키보드·큰 글씨·뒤로 가기. CSS 모의 폭과 실물 구분 |
| iPhone 16 Pro | 세로/가로·안전 영역·키보드·앱/브라우저 왕복·사진/HEIC·취소. 기존 Safari와 새 WKWebView 구분 |
| PC 관리자 | 125/150% 확대·실제 여유 공간 메뉴·일괄 선택·표 내부 스크롤·초점·다운로드 |

페이지 전체 가로 넘침·글자 잘림·중복 행·가려진 주요 조작이 없어야 한다. 필요한 표 안에서만 가로 이동한다. 터치 영역은 최소 44 CSS px를 목표로 유지하고 고령 기사님의 글씨·버튼을 줄여 압축하지 않는다. 회전·키보드 전후 입력·선택·저장 상태를 보존한다.

위치는 정상 수신 구간의 서버 접수 간격 30초 이내를 목표로 한다. 추정 정확도와 실제 거리 오차를 구분하고 미달·정체·배터리 소모·원인을 기록한다. 종료 후 중단과 관리자/보호자 표시까지 대조한다.

## 정책·자료 준비 원칙

- 개발자 계정 결제 기록만으로 조직·게시 권한을 확정하지 않는다. 콘솔·계약을 확인하며 암호·개인 기기 ID·인증서/키는 Git·문서·Issue·로그에 남기지 않는다.
- TestFlight 없이 등록 기기 개발/Ad Hoc 시험도 가능하지만 Apple 팀·기기 등록·프로파일·서명은 필요하다. simulator zip으로 대체하지 않는다. [Apple 기기 배포](https://developer.apple.com/documentation/xcode/distributing-your-app-to-registered-devices)
- 수업/셔틀은 물리적 서비스 기준으로 결제를 검토하며 PG 비용까지 0%라고 안내하지 않는다. 디지털 상품은 별도 검토한다. [Google 결제](https://support.google.com/googleplay/android-developer/answer/9858738?hl=en), [Apple 심사지침](https://developer.apple.com/app-store/review/guidelines/)
- 위치·학생 사진·Gemini로 전송되는 음성·납부·건강 관련 결석 사유를 실제 활성 경로와 대조한다. 위탁/공유·보관·암호화를 전체 경로 확인 없이 단정하지 않는다.
- Android target 36은 API 수준 조건에 대응한다. Apple은 2026-04-28부터 iOS 26 SDK 이상 요구. 빌드 성공은 심사 적합성 보장이 아니다. [Google 대상 API](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en-mt), [Apple SDK](https://developer.apple.com/news/?id=ueeok6yw)
- Google 12명·14일 시험은 해당 신규 개인 계정 기준이다. 업턴랩스 실제 유형 확인 후 판단한다. [Google 시험 요건](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en)
- 앱 내 삭제와 외부 웹 요청 경로·보관 예외를 함께 확인한다. WebView/통합 앱이라는 이유만으로 Apple 4.2/4.3 통과를 보장하지 않는다. [Google 삭제](https://support.google.com/googleplay/android-developer/answer/13327111?hl=en-EN), [Apple 삭제](https://developer.apple.com/support/offering-account-deletion-in-your-app/)

2026-10-28까지 확인한 공식 출처 기준이며 제출 직전에 재확인한다. 상세 목록은 [스토어 준비](store-release.md), 구체적인 시험·차단 항목은 [실기기·출시 준비 원장](native-device-release-readiness.md)을 함께 사용한다. 다음 그룹은 소유 파일·시험 환경·누락 해결 범위를 묶어 승인 후 진행한다.
