## 앱 구조

역할별 별도 앱 네 개를 만들지 않고 하나의 STIZ 앱에서 기존 서버의 역할 판단으로 분기한다. iOS는 학부모·선생님·관리자, Android는 이 역할과 기존 기사님 위치 공유 기반을 준비한다. 앱을 설치했다는 사실은 권한이 아니다. 로그인 후 서버가 허용한 메뉴만 열린다.

- Android: `apps/driver-android/UNIFIED_FOUNDATION.md`. 기존 위치 서비스·정지 서버 확인·기기 저장소·TLS 시험 경계를 유지한다.
- iOS: `docs/stiz-ios-codemagic.md`. BDR와 같은 Codemagic 원격 Mac 방식을 쓰되 현재 산출물은 시뮬레이터용 `.app.zip`이며 IPA/TestFlight는 다음 단계다.
- 네이티브 간편로그인·본인인증의 안전한 브라우저 인계는 아직 없다. 브라우저 로그인을 앱 로그인 완료로 표시하거나 쿠키/인증 토큰을 복사하지 않는다.
- Android `/staff/run`은 로그인 계정에 결합된 경로다. 이를 공개 `/driver/<token>` 주소로 몰래 변환하면 로그아웃·권한 회수 경계를 약하게 만들 수 있어 금지한다. 현재는 명확한 미지원 안내를 제공하며 로그인 기반 운행 연계는 다음 보안 그룹에서 해결한다. 기존 전용 기사 링크 모드는 유지한다.
- Android 통합 WebView의 파일 선택(`onShowFileChooser`)·외부 결제 앱 복귀·FCM/APNs는 아직 구현하지 않았다. 따라서 선생님 사진 업로드 등 웹 기능이 있다는 사실만으로 통합 앱에서 사용할 수 있다고 판단하면 안 된다. iOS의 파일 선택/복귀도 실빌드·실기기 검증 전이다.

## 내 계정과 탈퇴

- `/account`, `/account/withdraw`는 자녀 보유 여부와 무관하게 현재 Auth에 직접 연결된 본인만 사용한다. 이름·전화번호·이메일만으로 다른 사용자를 연결하지 않는다. 기존 학부모 경로도 유지한다.
- 공개 탈퇴 실행 함수 안에서 현재 인증·대상·최신 역할·탈퇴 요청을 재검사한다. 다른 보호자나 직원이 임의 계정 ID를 전달해도 삭제되지 않는다.
- 수강·담당 업무가 없는 일반 학부모는 즉시 처리할 수 있고, 수강·직원 역할·담당 수업/운행이 있으면 검토한다. **ADMIN/VICE_ADMIN 자동 삭제는 지원하지 않는다.** 관리 권한 이관과 지원 처리 절차를 출시 전 추가 확정해야 한다.
- 학생·출결·수납 이력은 보존한다. 실제 탈퇴 시 로그인 수단을 먼저 삭제한 뒤 개인정보·연결·푸시 구독을 정리한다. 이 작업에서는 합성 데이터와 가짜 인증 공급자만 사용한다.
- 외부 Auth 삭제는 DB 거래를 되돌려도 복구되지 않는다. Auth만 삭제되고 DB 정리가 실패하면 신청 표시는 유지하고 관리자가 다시 처리해야 한다.
- 이 부분 실패에서 옛 JWT(아직 유효해 보이는 로그인 증표)가 남아도 접근할 수 없도록 공통 인증의 빠른 경로에서 직접 연결된 탈퇴 관련 계정 상태를 DB에서 다시 읽는다. 완료는 거절하고 신청 중은 Auth 서버에 실제 로그인 유효성을 다시 확인한다. 일반 계정의 기존 인증 정책은 유지하되 인증당 DB 조회 1회가 추가된다.
- 취소·관리자 반려도 같은 계정 행을 잠근 다음 인증을 재확인한다. 이미 Auth가 삭제됐거나 확인에 실패하면 신청 표시를 지우지 않는다. 그래야 처리 실패 후 반려로 옛 로그인 증표가 다시 통과하는 일이 없다.
- 완전 익명화 후 Auth 연결 칸이 비어 직접 매칭되는 학원 계정이 없어도 Auth 서버 재확인을 거친다. 서로 다른 두 계정이 같은 Auth에 연결되는 모호한 상태는 거절한다. 관리자 반려에서 명시적 Auth 연결이 없는 기존 계정은 임의 추정하지 않고 보류한다.
