# 사이트 월 운영 장부 — 운영 적용 전 확인

## 현재 범위

- `/admin/finance/monthly-ledger`의 학생별 링크에서 `/admin/finance/monthly-register`로 이동한다.
- 학생·월 하나에 반별 기간/상태/기준금액/할인/이월/일할 차감과 근거를 기록한다. 셔틀비는 학생 월 단위로 한 번만 합산한다.
- 초안 저장 → 저장본 확정 → 사유를 남겨 재열기 순서다. 매 작업마다 새 버전과 전체 내용의 감사 기록을 같은 거래에 저장한다.
- 관리자 직접 입력 장부이며, 시트 대체 완료나 세 시스템 동기화 완료를 뜻하지 않는다. 확정도 청구서 발행 승인이 아니다.
- 월초/기간/정책 금액을 자동 채우지 않는다. 현재 등록 이력이 있는 반만 입력 가능하며, 현재 수강/휴원 반이 빠지면 확정을 막는다. 과거 월 제외 반도 상태와 0원 근거로 명시한다.
- 금액 공제는 승인 근거의 수동 입력이다. 이월 잔액의 차감·소진 추적, 다음 달 자동 이전, 연간 일정 기반 일할 자동계산은 아직 없다.

## 안전한 기본값

- `MONTHLY_REGISTER_WRITES_ENABLED`는 미설정 또는 `false`가 기본이다. POST는 관리자라도 503으로 차단된다.
- 저장을 허용하려면 아래 검증과 사용자 승인을 먼저 완료한다. 이 작업에서는 환경변수를 설정하지 않았다.
- DB 구조가 없으면 GET은 준비 상태를 확인하라는 오류를 반환한다. 조회 시 테이블을 자동 생성하지 않는다.
- `MonthlyEnrollmentRegister`와 `MonthlyEnrollmentRegisterRevision` 외에는 쓰지 않는다. Enrollment, Payment, 시트, Rallyz, 문자·푸시에 연결하지 않는다.
- 저장 결과가 불확실하면 재시도하지 않고 재조회한다. 버전이 바뀐 오래된 요청은 409로 막아 이중 저장을 방지한다.

## 운영 적용 전 필수 검증

1. 별도 테스트 DB의 정확한 프로젝트/접속 대상 확인. 운영 DB URL을 테스트에 사용하지 않는다.
2. `20260904121549_add_monthly_enrollment_register/migration.sql`을 검토한다. 2026-09-04에 격리된 로컬 PostgreSQL 16의 가상 자료로 실행 검증했다. 운영 DB에는 미적용이다.
3. 테스트 DB에 새 두 테이블만 적용한다. 전체 미적용 migration을 운영에 일괄 실행하지 않는다.
4. RLS 활성, PUBLIC/anon/authenticated 권한 없음, 서비스 역할의 감사 이력 UPDATE/DELETE/TRUNCATE 금지를 실제 역할별로 조회/시험한다. Prisma 서버 계정의 최소 권한도 확인한다.
5. 다반·휴원·이월·중간 시작의 초안/확정/재열기 저장·재조회, 동시 두 창 저장, 감사 INSERT 실패 시 전체 롤백을 실제 DB에서 검증한다.
6. 이름이 같은 두 학생, 과거 등록 반, 긴 한글 근거, 응답 중단 후 재조회, 월/학생 변경 중 화면 상태를 테스트 브라우저에서 검증한다.
7. 기존 등록/청구 경로가 수정되지 않았는지, 전체 장부/감사 기록이 백업에 포함되는지, 복구 후 버전·합계가 같은지 검증한다.
8. 운영 적용은 대상 DB·새 테이블·기존 자료 변경 없음·쓰기 잠금 유지라는 미리보기를 사용자에게 승인받은 후 별도 시행한다. 활성화도 제한된 대상의 시험 저장 승인 후 진행한다.

## 아직 필요한 시트 대체 작업

- 시트의 대상 월·반별 기록과 새 장부를 건수/금액/상태 단위로 읽기 전용 대조하고 이관 미리보기 작성.
- 할인 정책·이월 잔액/사용 이력·일할 회차 근거 자동 검증 및 실제 Payment/Invoice의 반별 귀속.
- 학교스포츠클럽 수납·토스 대조·메모·통계·셔틀 등 시트 전용 기능과 백업/복구 동등성 검증.
- 사이트를 최종 기준으로 승격하는 별도 승인 전에는 기존 시트/Rallyz 대조를 유지한다.

## 로컬 실제 DB 검증 (2026-09-04)

- 실행: `node scripts/test-monthly-register-postgres.mjs` (Windows, PostgreSQL 16 기본 설치 경로 필요).
- 새 `.tmp/monthly-register-pg-*` 클러스터와 `127.0.0.1:55432`만 사용한다. 환경 파일·운영 DB URL·기존 5432 서버는 사용하지 않는다. 포트 사용 중이면 중단한다.
- 접속한 DB 이름·주소·포트·실제 데이터 폴더를 대조한 뒤 가상 학생 4명과 반 2개만 생성한다. 기존 migration 파일을 그대로 실행한다.
- 실제 DB 검사 37개 통과: 저장/확정/재열기, 첫 저장·수정 경쟁(1건 성공/1건 충돌), 감사 실패 시 전체 롤백, 역할별 권한/RLS, DB 제약조건, 읽기 전용 거래, 원 수강자료 불변, 백업 복원 일치.
- `pg_dump` 결과를 같은 임시 클러스터의 별도 DB에 복원해 장부·전체 감사·버전·RLS·권한을 비교했다. 최종 장부 4건과 감사 11건을 확인했다.
- 정상 완료/실패/중단 신호에서 소유한 임시 DB만 종료한다. 임시 인증 파일은 제거하며 합성 자료·백업·로그는 Git 제외 폴더에 보존한다. 강제 프로세스 종료/PC 전원 차단까지 정리를 보장하지는 않는다.
- 제한된 Windows 실행 권한에서는 `pg_ctl` restricted token 오류가 날 수 있다. 승인된 로컬 검사에 한해 권한 확장 후 재실행한다. 기존 서비스에 붙는 우회는 하지 않는다.
- 추가 검증: 기존 회귀 88개, TypeScript, 변경 파일 ESLint 통과. 실제 브라우저 E2E·운영 Supabase 역할/전체 스키마 호환·이관 대조는 아직 미검증이다. 이 결과만으로 운영 쓰기 잠금 해제나 시트 중단을 승인하지 않는다.

## 격리 브라우저 기능 검증 (2026-09-04)

- 실행: `node scripts/test-monthly-register-browser.mjs`. 설치된 Chromium/Chrome/Edge를 사용자 프로필과 분리된 헤드리스 모드로 실행한다. 임의 URL이나 인증 인수는 받지 않는다.
- 실제 `MonthlyRegisterClient.tsx`와 계산 모델·React를 임시 번들로 실행한다. 가상 학생 두 명은 이름을 같게 두고 안정 ID로 구분한다. 모의 API 응답만 사용하며 운영 DB·인증·실제 API는 호출하지 않는다.
- loopback 자동 포트의 정적 서버, 번들 의존 모듈 허용 목록, 브라우저 요청 허용 목록과 CSP로 범위를 제한한다. `/api`는 서버에서 404이며 테스트가 직접 가로채 가상 응답을 제공한다.
- 기능 검사 13개: 빈 입력 차단, 다반 합계·저장/확정/재열기·이력, 누락반/미저장 확정 차단, 빠른 중복 클릭, 409/500/요청 중단, 저장 후 응답 유실과 재조회, 동명이인·학생/월 변경, 지연 조회 중 입력 변경 잠금, 쓰기 off/미등록 반 잠금, 응답 ID 불일치 차단.
- 최초 진단에서 발견한 미저장 새로고침 유실을 보완했다. 현재 기능 검사 19개·진단 0개가 통과했다. 새로고침 취소/승인, 링크 취소/승인, 미편집 무경고, 사유/미리보기 보호, POST·결과 재조회 중 이동 차단, 결과 불일치 후 경고 유지를 추가했다.
- 한계: Next Link는 anchor로 대체했고 운영 스타일 전체는 재현하지 않는다. 실제 로그인·Next 라우터·브라우저→운영 API→DB 연속 E2E, 응답 역전 경합은 통과로 주장하지 않는다.
- `.tmp/monthly-register-browser-*`에 합성 화면 스크린샷과 결과 JSON을 보존한다. 정상/실패 종료 시 소유한 브라우저와 정적 서버만 닫으며 푸시·배포·운영 쓰기 활성화는 하지 않는다.

## 미저장·저장 결과 미확인 상태의 이탈 보호

- 편집·작업 사유·미리보기·미확인 저장 결과가 있으면 새로고침/문서 닫기에 브라우저 기본 경고를 표시한다. 같은 창 HTTP(S) 링크는 별도 확인하며 취소하면 화면과 편집을 보존한다. 새 창 링크·다운로드·문서 내 해시는 이동 경고에서 제외한다.
- POST 처리 또는 결과 재조회 중에는 같은 창 링크 이동을 차단한다. POST 응답 성공만으로 경고를 해제하지 않고 GET 결과까지 확인한다. 실패/응답 유실/대상 불일치 후에는 재조회 전 이탈 경고를 유지하며 자동 재전송하지 않는다.
- 이벤트와 타이머는 해제하며, 원장·청구·수납·외부 발송 로직은 바꾸지 않는다. 저장 기능의 기본 off도 유지한다.
- 강제 종료·일부 모바일 종료·동일 문서의 뒤로가기/프로그램 라우터 이동까지 보장하지 않는다. 새로고침 경고도 사용자가 이탈을 승인할 수 있다. 플랫폼 한계는 [MDN beforeunload 안내](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event)를 따른다. 운영 Next 라우터 통합 검증은 별도다.

## 실제 API·권한·화면·격리 DB 통합 검사

- 실행: `node scripts/test-monthly-register-postgres.mjs --with-api-browser`. 기존 37개 DB 검사 뒤 같은 임시 클러스터에서 추가 검사하고, 그 결과까지 백업·복원한다. 기존 무인수 실행도 유지한다.
- 실제 React 화면 요청을 테스트 브리지로 전달해 실제 `NextRequest/NextResponse`, 월 장부 API, `requireAdmin`, 저장 서비스를 실행한다. Prisma 연결 대신 소유권을 확인한 로컬 PostgreSQL 어댑터를 주입하며 GET의 반복 읽기/읽기 전용 거래도 적용한다.
- Supabase 제공자 응답만 가상으로 만든다. 관리자 권한은 실제 `User` 표의 역할로 판정하며, Auth ID와 DB 사용자 ID를 다르게 두어 감사 작성자 귀속을 확인한다. 인증 metadata의 관리자 표시는 권한 근거로 사용하지 않는다.
- 테스트는 합성 계정과 학생만 사용한다. 실제 로그인·토큰 서명·쿠키·세션 갱신·Supabase SDK·Next middleware/layout/라우터 전체 흐름·운영 전체 스키마는 검증하지 않는다. 화면 요청은 Playwright에서 실제 라우트 함수로 연결하므로 Next HTTP 서버 전송 계층 검증도 아니다.
- 테스트의 저장 허용 값은 요청별 격리 상태에만 둔다. 운영 환경 파일이나 프로세스의 저장 설정을 바꾸지 않으며, 운영 인증·DB 연결·문자·카카오·청구 발행·배포는 실행하지 않는다.
- DB 역할 캐시는 실제 코드와 동일하다. 역할별 고유 이메일/새 브리지 인스턴스로 시험을 분리하며 이 검사로 운영 역할 변경의 즉시 반영을 보장하지 않는다.
- 통합 20개 통과: 익명/학부모/강사/기사/미등록/metadata 조작 차단, 관리자·부원장 및 fallback, 병렬 요청 설정 분리, 쓰기 잠금/출처/입력 형식 차단, 실제 저장·확정·재열기·감사 작성자, 버전 충돌, 최초 저장 응답 유실 후 확인창 승인·재조회·중복 방지, 합성 원본 불변. 별도 브라우저19·회귀87·TypeScript·ESLint도 통과했다.
- 최종 재실행에서 기존 DB 검사와 백업/복원 37개도 모두 통과하고 임시 DB 종료를 확인했다. 합성 User까지 백업 복원 비교하며 기본 ACL의 NULL/명시 표기는 실효 권한으로 정규화한다. 증거는 `.tmp/monthly-register-browser-mKFjaO/api-db-result.json`과 `.tmp/monthly-register-pg-NGnkcG/`에 보존한다.
