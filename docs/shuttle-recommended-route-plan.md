# 추천 배차·기사 조정·원장님 최종 확정

## 승인 범위

2026-11-04 사용자가 원장님 최종 확정 방식을 선택했다. 로컬 구현과 합성 자료 검증만 진행한다. 운영 DB·실제 배차·문자·청구·푸시·배포는 실행하지 않는다.

## 업무 흐름

1. 로그인한 담당 기사가 운행 화면의 신규 요청을 연다.
2. 해당 월·요일·등하원 구간에 신규 학생을 추천·미확정 상태로 표시한다. 아직 탑승 체크 대상은 아니다.
3. 기사님이 드래그 또는 위·아래 버튼으로 정차를 조정하면 개별 이동 구간으로 시각을 다시 계산한다. 수업·정원·다음 운행·이미 지난 정차를 확인한다.
4. 조정 결과를 원장님에게 제출한다. 제출만으로 실제 명단이나 문자 발송을 확정하지 않는다.
5. 원장님이 변경 전후 시각·영향 학생·문자 수신 대상과 문안을 한 번 확인하고 확정한다.
6. 명단·확정 노선·적용일·검토 상태·안내 대기 기록을 같은 변경 버전으로 보존한다. 문자 접수와 전달 성공은 구분한다.

## 시각과 안내 기준

- 수동 확정 분 → 계산 분 → 유효한 표시 문자열 순서로 기사 화면·저장·문자 시각을 통일한다. 시각은 0~1439 정수 분으로 다룬다.
- 구간별 실도로 시간이 없는 경우 추정임을 표시한다. 전체 소요시간을 직선거리 비율로 나눈 값을 실도로 구간 확인으로 취급하지 않는다.
- 기존 학생은 마지막 전달 성공 안내 또는 원장님이 명시 확인한 안내 기준과 최종 시각을 비교한다. 앞당김·늦어짐 모두 5분 이상이면 대상이다. 3분씩 두 번 바꾼 누적 6분도 포함한다.
- 신규 학생의 최초 확정 안내, 장소·이용 요일·방향 변경은 별도 안내 사유다. 한 학생의 여러 구간 변경은 한 문안에 묶는다.
- 기존 학생의 안내 기준이 없는 경우 최초 안내로 추정해 전원 발송하지 않는다. 기준 확인 필요로 남긴다. 미확인이나 실패한 문자를 전달 성공으로 저장하지 않는다.
- 임시 조정·미리보기·초안 저장 중에는 실제 문자 발송을 실행하지 않는다. 최종 확인한 버전·대상·문안과 다른 발송은 보류한다.

## 권한과 이력

- 공용 운행 토큰에 신규 학생 정보·초안 확정·발송 권한을 추가하지 않는다.
- 기사님은 본인에게 지정된 요청과 해당 운행 구간의 초안만 조정한다. 실제 확정은 관리자만 한다.
- 저장 노선이 없으면 현재 명단에 기반한 초안임을 표시한다. 차량 또는 운행 담당이 모호하면 원장님의 명시 확인을 요구한다.
- 적용일 이전의 운행·탑승 기록을 현재 편집으로 다시 쓰지 않는다. 이미 탑승했거나 지난 정차는 조정하지 않는다.
- 조회는 읽기만 한다. 늦게 온 응답과 오래된 편집 버전을 덮어쓰지 않는다. 결과 불명의 문자를 자동 재발송하지 않는다.

## 검증 계획

순수 계산·UI 행동·API 권한·실제 Prisma 격리 DB·합성 브라우저를 구분해 검증한다. 외부 경로 공급자와 문자 공급자는 합성 어댑터를 사용하며 운영 주소·연락처·키를 사용하지 않는다. 구체적인 완료 결과는 검증 후 이 문서와 scratchpad에 기록한다.

## 실제 조작 중 보완

- 브라우저 기본 끌기와 손잡이 포인터 처리가 겹쳐 실제 드래그가 실패했다. 손잡이의 포인터 방식으로 통일하고 실제 마우스 입력으로 순서 변경·시각 재계산을 재확인했다.
- 320px에서 조정 저장 실패 시 입력을 유지하고 제출을 막는다. 재계산 성공 후에만 제출하도록 했다. 버튼은 44px 이상, 입력 글씨는 16px 이상을 유지한다.
- 제출 뒤 문제가 발견되면 원장님이 기사님께 수정 요청하여 초안으로 돌린다. 수정 요청은 실제 운행·학부모 안내를 바꾸지 않는다.
- 문자 대상 계산과 발송 대기 기록은 실제 문자 전달과 다르다. 로컬 검증에서는 합성 공급자를 사용하며 운영 발송 활성화·예약 작업 구성은 하지 않는다.

## 구현 경로

- 로그인 기사: `/staff/run`의 신규 요청 → 담당 요청 선택 → 추천 위치·시각 조정 → 원장님 제출. 공용 운행 링크에는 진입점과 권한을 추가하지 않는다.
- 관리자: `/admin/shuttle/plan-drafts`에서 변경 전후·다른 학생 영향·문자 대상을 확인한다. 수정 요청은 초안으로 되돌리고, 오래된 초안은 초기화 동의와 새 적용일로 재구축한다.
- 서버: `route-plan-query.ts`의 원본 지문·수정번호 검증, 원장님 최종 확정, 날짜별 이력 보존. 외부 도로 견적은 DB 변경 거래 밖에서 준비하고 저장 직전에 원본을 다시 검증한다.
- 문자: `route-plan-outbox.ts`와 `route-plan-worker.ts`가 기존 문자 정책·발송 장부에 연결한다. 발송 전 현재 보호자·번호·배차를 재확인하고, 결과 불명은 자동 재전송하지 않는다. 실제 발송은 기본 비활성이다.
- 신청 처리함: 새 문자도 현재 보호자와 모든 확정 구간에 맞는 전달 성공만 `안내 완료` 근거로 읽는다. 접수·실패·부분 구간은 완료로 올리지 않는다.
- 기존 월별 명단·배차 편집에는 미래 적용일을 표시한다. 현재 날짜의 기사님 수정은 미래 배차 원본을 덮지 않고 날짜별 변경으로 저장한다.

## 운영 적용 전 별도 단계

이번에는 로컬 코드·합성 검사만 진행했다. 운영 DB 구조 적용·기존 요청 재배차·실제 문자·푸시·배포는 하지 않았다.

- 신규 구조는 초안·확정 버전·안내 대기열·안내 기준·기존 편집 이력 **5개 표**, 기존 명단/노선 변경을 기록하는 statement trigger **6개**, 함수 **1개**다. RLS·공개 접근 차단을 포함하며 실제 적용은 별도 승인 대상이다.
- 실도로 응답 시간과 실제 차량의 승하차 동선은 검증하지 않았다. 실제 지도 연결 전후 제한 시간·정원·인접 운행을 다시 대조한다. 확인되지 않은 도로 구간은 확정을 막는다.
- 운영 문자 활성화와 공급자 전달 결과 수집 실행은 별도 승인·설정 후 검증한다. 활성화 전에는 화면에도 `문자 자동 발송이 꺼져 있습니다. 배차만 확정했습니다.`라고 표시한다.
- 현재 운영의 기존 기사 검토 요청과 실제 배차·학부모 안내는 그대로 보류되어 있다. 이 로컬 기능 검증은 기사님의 실제 가능 시각 확인을 대신하지 않는다.
