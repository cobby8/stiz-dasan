# 가족 연결과 공통 스포츠 스타일

2026-10-27. 사용자 승인 범위는 로컬 코드 수정·합성 자료 검증이다. 운영 DB 적용, 실제 인증·문자·푸시 발송, 채널 저장, 푸시·배포는 포함하지 않는다.

## 승인된 정책

- 추가 보호자는 본인 명의 인증 후 기존 연결 가족의 이름·연락처와 자녀 이름을 입력한다. 등록 정보가 정확히 일치하는 한 대상에게만 요청을 접수한다.
- 승인 전에는 자녀 정보나 후보 가족·학생 목록을 신청자에게 공개하지 않는다. 미일치·중복·부적격은 같은 실패 안내로 처리하며 실제 저장 없이 완료라고 표시하지 않는다.
- 기존 연결 부모가 없는 미성년자는 요청을 접수하지 않는다. 학원 승인·관리자 대신 승인·시간 경과 후 자동 승인 경로를 만들지 않는다.
- 학원이 등록한 보호자 이름·번호와 서버에서 확인한 본인인증 결과가 명확히 일치하면 현재 계정에 접근 권한을 추가한다. 모호한 가족·계정은 자동으로 고르지 않는다.
- 성인 본인은 본인 이름·생년월일·학생 연락처를 함께 대조한다. 성인반이라는 반 이름만으로 예외를 열지 않는다. 성년 기준은 민법 제4조의 만 19세이며 생일 전후를 검증한다.
- 기존 Student.parentId, 대표 보호자·청구 수신자, 수강 이력, 로그인 계정과 관리자·교사·기사 역할은 교체하지 않는다.
- 추가 보호자는 수강료·납부 상태를 확인하고 기존 입금 알림·영수증 요청을 이용한다. 온라인 결제·개인 결제 영수증 직접 열람은 기존 대표 보호자만 유지한다. 대표 보호자의 결제 고객 키나 저장 수단을 추가 가족과 공유하지 않으며, 해당 버튼도 숨긴다.

## 변경 그룹과 소유권

| 그룹 | 담당 | 결과물 |
|---|---|---|
| 서버·권한 | parent_link_audit | 연결·요청·단회 인증 원장, API, 공통 자녀 접근 판정 |
| 화면·공통 스타일 | workspace_style_audit | 흰색·차콜·오렌지 공통 테마, 빈 화면·계정 링크·가족 승인함 |
| 브랜드·통합 | PM | 공식 STIZ 인증 로고, 활성 배포 사전검사, 기록·통합검증 |
| 독립 검증 | public_style_ssr_qa | 격리 PostgreSQL·모의 인증·실제 UI 브라우저 검증 |

서버·UI는 독립 구현 후 통합한다. tester는 운영 인증·데이터를 사용하지 않고 실제 소스와 합성 자료를 대조한다.

## 안전한 실행 경계

- 기능은 CHILD_CONNECTIONS_ENABLED=true일 때만 연다. 인증 설정은 CHILD_CONNECTIONS_SECRET(또는 PARENT_SIGNUP_SECRET), PORTONE_V2_API_SECRET, NEXT_PUBLIC_PORTONE_STORE_ID, NEXT_PUBLIC_PORTONE_IDENTITY_CHANNEL_KEY가 필요하다. 기본값은 비활성이다. 새 표가 없는 환경에서는 기존 보호자 접근을 그대로 사용한다.
- ParentStudentAccess는 추가 접근 권한이며, ChildLinkRequest는 기존 보호자에게만 보내는 요청 원장이다. ChildIdentityChallenge는 이 계정·기기의 인증을 1회만 사용하는 원장이다.
- 새 표는 브라우저 역할의 직접 접근을 막고 서버에서만 처리한다. 인증 결과는 브라우저 이름·번호를 신뢰하지 않고 공급자에게 다시 확인한다.
- 승인·거절·취소는 현재 권한과 상태를 다시 읽고 처리한다. 동시 승인·만료·타인 요청·자기 승인·인증 재사용을 막는다.
- scripts/child-connections-db-preflight.mjs는 활성 배포에서만 표·필수 컬럼·인덱스·강제 RLS·공개 접근 차단을 읽기 전용으로 확인한다. 자동 migration은 하지 않는다.
- 연결 요청 전달은 앱 안의 승인함으로 구현한다. 이번 로컬 검증에서는 실제 고객 문자·푸시·이메일을 보내지 않는다.

## 화면 원칙

- 공개 홈페이지의 흰색·차콜·번트오렌지를 공통 업무 토큰에 적용한다. 공개 페이지의 전체 CSS를 업무 화면에 덮어씌우지 않는다.
- 오류·결석·납부 등의 상태색, 기사님 큰 글씨·탑승 버튼·좁은 화면 배치는 유지한다.
- 자녀 없음·특강 신청 대기·연결 요청 대기를 구분한다. 계정 연결·역할 신청·탈퇴는 자녀 유무와 무관하게 접근한다.
- 설치 앱에서 신청 페이지가 브라우저로 열리는 경우를 검증하고 실제 이동 경로를 표시한다.
- 기존 학부모 화면의 권한은 완화하지 않는다. 자녀 없는 관리자·선생님은 인증된 계정의 별도 /account/children에서 같은 연결 화면을 사용한다. 설치 학부모 앱의 /mypage/children 경로도 유지한다.

## 인증 채널 준비 상태

- 포트원 콘솔에서 KG이니시스 통합인증 전용 채널 초안을 확인했다. 기존 mybdr 채널은 변경하지 않았다.
- 사용자가 STIZ 전용 MID·apikey 미발급이라고 확인했다. STIZ-본인인증 채널은 저장·생성하지 않았다. 전용 정보 발급 후 별도 실행 승인으로 저장과 환경 설정을 진행한다.
- 인증 요청의 inicisUnified.logoUrl에 HTTPS 공식 STIZ 로고를 지정했다. 이 설정은 계약 상점명·MID를 변경하지 않는다. 실제 인증창 표시는 공급자 연동 검증 전이다.
