# 통합 앱 사진 첨부·로그인 인계 후속

2026-10-28 사용자 승인: Android·iOS 사진 선택과 시스템 브라우저 로그인 인계를 로컬 구현·검증한다. 운영 데이터·인증 공급자·서명·원격 빌드·배포는 변경하지 않는다.

## 작업 그룹

| 그룹 | 담당 | 의존 관계 | 완료 기준 |
|---|---|---|---|
| Android 첨부·인증 | Android 담당 | 기존 GPS·탐색 정책 | 선택/취소/문서·촬영 연결, 개발 인증 기본 비활성, 로컬 빌드·정책 검사 |

## 바뀐 동작

- Android HTML 파일 입력을 시스템 선택창·카메라에 연결했다. 허용 형식·10개/25 MiB/합계 100 MiB·실제 사진 형식·권한·현재 페이지를 확인한다. 기존 CSV/JSON/Excel 입력도 유지한다. 전체 사진 접근 권한이나 WebView 로컬 파일 접근 허용을 추가하지 않는다.
- 파일 요청 번호는 회전 전후에 재사용되지 않게 하며 취소·화면 이동·복사 중 이동·Activity 종료에서 결과를 한 번만 마친다. 선택한 파일이 웹에 전달되기 전에 삭제되지 않도록 제한 캐시를 사용한다.
- iOS는 웹의 형식·복수 선택·촬영 설정을 처리하는 WebKit 기본 선택창을 유지한다. 촬영·사진 목적 문구를 추가했다. 실제 기기의 선택·취소 결과는 미검증이다.
- 개발 로그인은 시스템 브라우저에서 인증 후 앱 메모리의 비밀값과 짧은 일회용 코드가 일치할 때만 세션을 설치한다. 같은 코드를 동시에 소비해도 한 요청만 성공한다. 다른 앱 요청·다른 계정·탈퇴 계정·만료·재사용은 거절한다.
- iOS URL 변경 감지·완료 직전 페이지 검사, 두 앱의 완료 응답 중 중복 시작 차단, 실패·지연 안내와 기존 화면 복구를 추가했다.
- 새 앱 세션만 `__Host-stiz-native-session` 보호 표식을 사용한다. 서버 갱신과 로그인 이동 응답에서도 HttpOnly·Secure 쿠키를 보존하며 표식 없는 기존 웹 정책은 유지한다. 이 표식 자체는 권한 증명이 아니다.

## 남은 출시 조건

1. 새 iOS 코드의 원격 Xcode 컴파일과 실제 iPhone 시험. 이전 Codemagic #1 성공을 이번 수정본의 증거로 재사용하지 않는다.
2. Android 실제 선택창·촬영·회전·WebView FileList·압축→합성 서버 수신 시험. `setAllowContentAccess(false)` 상태의 선택 URI 실제 읽기는 미검증이다. iPhone HEIC 변환도 확인한다.
3. 실제 공급자 로그인·취소/만료/재시도·장기 세션·역할 변경·로그아웃 시험. 현재는 실제 공급자 대신 모의 인증을 사용했다.
4. 확정 앱 ID·서명·검증된 HTTPS App Link/Universal Link 및 시험용 HTTPS 환경 연결. 개발 커스텀 주소는 로그인 소유권 검증을 대신하지 않으므로 Release와 production 서버에서 항상 차단한다. 기본 역할 홈 로그인 외 상세 복귀·간편가입·로그인 수단 추가는 지원하지 않는다.
5. STIZ 전용 MID/apikey, 전용 본인인증 채널, 푸시·결제 복귀·계정 결합 기사 운행 등 남은 출시 작업. 본인인증 실제 시험을 임의의 BDR 채널로 대신하지 않는다.

정본: [서버 계약](native-auth-handoff.md), [Android](../apps/driver-android/MEDIA_AUTH_FOLLOWUP.md), [iOS](../apps/stiz-ios/MEDIA_AND_AUTH.md). 운영 DB·사이트·채널·발송·서명·원격 빌드·설치·푸시·배포 변경 없음.

가상 기기 시험을 위해 기존 SDK 이미지로 별도 AVD만 준비했다. 가상 기기 실행은 자동 승인 검토의 정책 차단으로 시작되지 않았다(구체 사유 미제공). 우회·기기 설치·실제 FileList 검사는 하지 않았다. debug 전용 합성 fixture는 후속 실행 준비이며 실제 파일 전달 성공의 근거가 아니다.
