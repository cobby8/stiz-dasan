# 실제 여유 공간에 따른 공개 헤더 메뉴

## 승인·범위·그룹

사용자는 여유 공간이 있어도 폭 기준으로 메뉴가 사라지는 문제를 수정하도록 승인했다. 공개 헤더·스타일·크기 판단·가이드 연결만 바꾸며 메뉴·계정 기능·API·자료·운영 설정은 유지하고 배포하지 않는다.

| 그룹 | 담당 | 의존 관계 | 완료 기준 |
|---|---|---|---|
| 실제 크기 판단·헤더 | PM, 콘텐츠 담당 독립 읽기 검토 | 기존 헤더 구조 확인 | 고정 폭 제거·한 줄 실제 합계로 접힘/펼침·접힌 항목도 측정 |
| 가이드 연결 | 탐색 담당 | 헤더 `data-menu-layout` 계약 | 실제 모드 반영 후 안내 재판정, 기존 정리·단계 유지 |
| 브라우저 통합 | 독립 QA, PM 서버 단독 | 최종 빌드·소스 복사 | 여유 공간·큰 글씨·계정·연속 폭 전환·키보드·가이드 검증 |

## 원인·수정

- 이전 CSS는 일반1280px/큰 글씨1600px 기준으로 접었다. 창의 실제 가용 공간을 재지 않아 가운데가 비어 있어도 메뉴가 사라졌다.
- `useHeaderMenuFit`는 기존 로고·메뉴·계정·고정 버튼을 측정한다. 메뉴나 계정 컴포넌트를 복제하거나 별도 API를 호출하지 않는다.
- 접힌 메뉴와 데스크톱 계정 영역도 `width: max-content`로 실제 크기를 유지한다. `visibility: hidden`·`scale(0)`·절대 위치와 `inert`·`aria-hidden`으로 표시·포커스·페이지 넘침을 막으면서 `offsetWidth`를 읽는다.
- 펼침에 필요한 폭은 로고+메뉴+계정/버튼+실제 간격이다. 소수 픽셀 오차4px, 재확장 시 추가4px만 여유를 둔다. 경계의4px 구간에서는 현재 모드를 유지해 반복 접힘을 막는다. 화면 폭이나 큰 글씨에 별도 고정 접힘 기준은 없다.
- 행·로고·메뉴·버튼·계정의 `ResizeObserver`, 글씨 모드 클래스, 글꼴 준비/완료, 창 크기 변경을 관찰한다. 프레임마다 한 번만 합산하고 실제 결과가 달라질 때만 상태를 바꾼다. 종료 시 관찰·이벤트·예약 프레임을 해제한다.
- 헤더 첫 렌더부터 `data-menu-layout="drawer|expanded"`가 존재하며 실제 표시와 함께 바뀐다. Guide는 이 속성 변경도 기존 관찰자에 등록해, 비동기 크기 측정 뒤 실제 메뉴를 따라간다. 기존 observer 정리·세대 보호·같은 메뉴 단계 재시작을 재사용한다.
