# 관리자 업무와 청구 작업 통합

## 승인 범위

- 2026-10-20 사용자 승인: 관리자 메뉴·여백 정리, 결석·보강·이월 연결, 청구 제안·수정·일괄 발행의 로컬 구현과 검증.
- 운영 DB 변경, 기존 자료 삭제, 실제 청구 발행·발송, 푸시·배포는 제외한다. 운영용 저장 설정을 켜지 않는다.
- 기존 REA 런타임 조사와 공식 안내·Mobbin 화면 자료는 근거 수준을 구분한다. 랠리즈 Pro는 유료 미접근이며 plus 공식 자료를 Pro 직접 검증으로 간주하지 않는다.

## 확정 정책

- 같은 결석은 이월 또는 보강 중 하나만 적용한다. 이월 확정 시 미사용 보강권을 회수한다. 예약은 취소·좌석 해제와 함께 처리하고, 이미 사용·무단 불참 처리된 권리는 자동 전환하지 않는다.
- 이월 단가는 할인 후 원래 기간의 확정 수강료를 실제 예정 수업 수로 나눈다. 회차별 먼저 반올림하지 않고 적용 합계에서 원 단위 반올림한다. 다음 청구를 초과한 잔액은 보존한다.
- 질병·부상과 직계존비속 경조사는 증빙·관리자 확인 뒤 이월을 검토한다. 개인 사정·여행 등은 금액 이월 대상이 아니다. 사유만으로 금액을 자동 확정하지 않는다.
- 셔틀비는 결석 이월에서 제외한다. 여러 반 수강은 반별 청구를 유지하고 학생당 해당 기간 셔틀비 한 번을 지정 반의 청구에 포함한다.
- 기준 기간은 공식 연간 일정의 실제 수업일이다. 달력 월을 무조건 4회로 세지 않는다. 일정·기준금액이 없으면 계산을 보류한다.
- 기존 2026-10-05 보강권 발급 시작 결정과 과거 자료를 자동 소급하지 않는 원칙을 유지한다. 기발행·납부 청구는 덮어쓰지 않는다.
- 2026년 10월 신규 Google Sheet 장부를 만들지 않는다. 사이트를 업무 기준으로 삼되 랠리즈 외부 발행·전달의 확인은 별도이며 사이트 생성만으로 완료 표시하지 않는다.

## 목표 흐름

1. 기간 선택 → 유효 수강과 공식 일정·요금·기존 청구를 조회한다.
2. 결석·보강 상태·미사용 이월을 연결하여 반별 금액을 제안한다.
3. 정상/확인 필요/제외/이미 발행을 구분하고 변경·예외를 먼저 검토한다.
4. 행에서 항목별 수정과 사유 입력 → 저장 후 다시 조회 → 확정한다.
5. 선택 건수·총액·근거 버전을 확인하고 사이트 청구를 생성한다. 발행 직전 원본이 바뀌면 재검토한다.
6. 이월 사용과 청구 생성은 함께 성공하거나 함께 취소된다. 0원은 유상 청구 대신 정산 결과를 남긴다.
7. 사이트 생성·외부 반영·전달·납부 상태를 구분한다. 결과 불명은 재조회하고 무작정 재발행하지 않는다.

## 덜어낼 것과 보존할 것

- 주요 메뉴: 오늘 업무 / 신청·상담 / 원생 / 수업·출결 / 청구·수납 / 셔틀.
- 별도 결석·보강·입금 확인·수강 변경·카카오 접수·리포트는 해당 업무의 보조 진입으로 통합한다. 실제 통합이 끝나기 전 접근 경로를 없애지 않는다.
- 수납의 고정금액 자동 생성·대상 확인·청구 생성 입구는 청구 준비로 모은다. 구형 실행 코드는 대체 경로 검증 후 제거한다.
- 점검·이관·초기 좌표·연결 설정은 일상 목록보다 뒤에 둔다. 중복 설명·빈 대형 카드·반복 도구 줄을 줄인다.
- 금액 근거·버전·관리자 사유·동의·권한·백업·전달 실패·재조회 기능은 유지한다.
- 유니폼 본사 주문을 학원 청구에 임의로 합치지 않는다.
- 사용 여부를 확인하지 못한 서버 기능은 새 메뉴라는 이유만으로 삭제하지 않는다.

## 검증 기준

- 같은 결석 반복 저장, 출석 정정, 보강 예약·사용 후 전환에서 중복 보상 차단.
- 다반·할인·셔틀 한 번·면제·주말·중간 시작·휴원·퇴원·0원·잔액 초과.
- 원본·요금·출결·납부가 초안 이후 바뀌면 오래된 확정·발행 차단.
- 두 창 동시 저장·발행, 빠른 중복 클릭, 응답 유실·재조회에서 한 번만 반영.
- 실패 시 입력 보존, 성공/보류/실패 구분, 기존 발행·납부 기록 보호.
- 실제 자료는 가린 로컬 복사본에서 조회한다. 쓰기 검증은 별도 합성 자료 DB에서만 한다.
- 320/360px, 태블릿·PC에서 표·버튼·입력·팝업 겹침과 가로 넘침을 확인한다.

## 현재 상태

- 로컬 구현과 독립 검토를 마쳤다. 운영 적용·실제 발행·외부 전달 완료를 뜻하지 않는다.
- 주요 메뉴 6개와 보조 메뉴 3묶음으로 정리했다. 기존 보조 경로는 통합 전까지 유지하며, 청구 생성 입구는 `이번 달 청구 준비`로 통일했다. 구형 월 청구 실행도 새 저장 구조가 설치되면 차단하여 우회를 막는다.
- 새 검토표는 기본적으로 이번 발행 대상만 표시한다. 전체 이력은 필터에서 선택한다. 금액·기간·사유를 수정하고 저장 → 확정 → 선택 발행으로 진행한다. 사유별 보상 추천은 제공하되 증빙 확인과 최종 선택을 대신하지 않는다.
- `src/lib/billing/workbench-schema.sql`은 준비 파일일 뿐 운영에 적용하지 않았다. `STIZ_BILLING_WORKBENCH_WRITES_ENABLED`는 기본 꺼짐이며 운영에서 켜지 않았다. RLS·직접 접근 차단과 관리자 서버 경로를 함께 사용한다.
- 할인 후 원기간 확정 금액·실제 예정일을 보존하고 분수 잔액을 관리한다. 이월 확정·보강 회수와 청구·이월 사용은 각각 하나의 거래로 처리한다. 다른 창의 변경이나 원자료 변경은 재검토하도록 차단한다.
- 공식 일정은 기존 연간 일정 로더를 공유한다. 발행 전 최신 자료를 읽고 같은 일정 지문을 금액 근거에 보존한다. 조회 실패·불완전 반복 일정은 계산 성공으로 취급하지 않는다.

## 운영 전 남은 조건

- 실제 자료 미리보기는 이름·반·금액을 유지한 가린 로컬 복사본이며 저장은 차단한다. 운영 공식 달력을 이번 실행에서 가져오지 못한 경우 부분 일정도 복사하지 않고 계산을 보류한다. 운영 적용 전 실제 일정 연결을 재확인해야 한다.
- 기존 특강 보강권은 정규 이월로 자동 이관하지 않는다. 이미 사용한 보강, 원결석·출석 정정, 사용 청구 취소는 관리자 확인 대상으로 남긴다. 잔액을 조용히 복구하지 않는다.
- 누적 원장 조회가 안전 상한 5,000건을 넘으면 부분 계산 대신 차단한다. 누적량 증가 전 조회 범위를 개선해야 한다.
- SQL 적용·저장 활성화·기존 원장 대조·실제 대상/총액 확인·발행 승인은 별도다. 사이트 청구 생성과 랠리즈 발행·학부모 전달 상태는 구분한다. 랠리즈 자동 발행은 이번 구현에 포함되지 않는다.
- 토스 운영 키 준비 전 배포 보류와 Git 자동 배포 차단을 유지한다. 새 푸시도 실행하지 않았다.

## 최종 실제 자료 미리보기

- 27개 업무 테이블의 가린 자료를 로컬 DB에 복사하고 운영 연결을 종료했다. 최종 생산 빌드 성공, 소스 867개 해시가 현재 작업본과 일치했다.
- http://127.0.0.1:4090/admin 에서 홈·신청·원생·수납·청구 준비·정규 배차 연결을 확인했다. 청구 486이력 중 기본 대상6, 조회200/쓰기403을 재확인했다.
- 공식 달력 조회는 UNAVAILABLE로 남았다. 부분 일정을 복사하지 않았으며 실제 수업일이 없는 청구는 발행 보류한다. 원생/수납 자료 검토는 가능하지만 실제 금액 확정 완료로 해석하지 않는다.
- 위치 좌표·지도 키는 복사하지 않아 배차 지도/최적화 실동작은 이 실제자료 미리보기에서 검증하지 않는다. 합성 검증과 운영 적용을 구분한다.
- 최종 증거: `.tmp/real-data-preview/{summary,source-proof,billing-verification}.json`. 시험 DB는 실행기 소유이며 종료할 때 정리한다. 별도 종료된 합성PG 잔여 폴더1개는 자동 승인 정책이 정리를 차단해 그대로 보존했다.
