# STIZ 기사님 안드로이드 앱과 화면 밖 위치 공유

2026-10-19 · 출시 주체: **업턴랩스** · 앱 이름 초안: STIZ 기사님

## 현재 웹의 실제 동작

기존 `useGpsShare`는 브라우저의 `watchPosition`과 화면 안의 10초 타이머를 사용한다. 화면을 떠나 컴포넌트가 해제되면 수집을 중단한다. 화면 잠금·다른 앱 전환 때 반드시 즉시 중단되는 것은 아니지만, 브라우저가 실행을 멈출 수 있어 지속 공유를 보장할 수 없다. PWA 설치만으로 이 제한을 해결하지 못한다.

이전에 완료한 브라우저 검증은 합성 위치·통신에 대한 저장 상태 검사이며 실제 휴대폰의 백그라운드 실행 증명이 아니다. 기존 단정적 경고도 ‘웹에서는 화면 잠금·다른 앱 이동 시 위치 공유가 멈출 수 있습니다’로 바로잡았다.

## 구현 그룹과 경계

| 그룹 | 담당 | 의존 관계 | 결과 |
|---|---|---|---|
| 기존 위치·권한 조사 | 읽기 전용 조사 | 현재 웹·서버 | 웹 수명, 수신 시각, 기기 경합 문제 확인 |
| 안드로이드 앱 | 앱 담당 | 공통 API·메시지 계약 | 앱 전용 폴더, 원본 기사 UI·독립 위치 서비스 |
| 서버 운행·관리자 상태 | 서버 담당 | 계약 | 세션·단일 기기·신선도·종료 차단, 노후 위치 표시 |
| 웹과 앱 연결 | PM | 계약; 앱/서버와 파일 독립 | 실제 hook·기기 상태 복구·중복 GPS 방지 |
| 독립 검토·통합 검사 | reviewer / PM | 구현 후 | 오류·토큰 전환·중단 확인·DB 경합 검증 |

운영 DB·환경값·사이트 배포·스토어 업로드는 이 구현에 포함하지 않았다. 신규 기능은 서버 설정 `DRIVER_MOBILE_TRACKING_ENABLED`가 정확히 `true`일 때만 활성화한다. 기본은 꺼짐이다.

## 앱 동작

- 안드로이드 8(API 26) 이상을 대상으로 Java 기반 앱을 만들었다. 기존 라벤더 퍼플 운행 화면은 WebView로 표시한다. 공식 로고 PNG를 재색칠하지 않고 사용한다.
- 기사가 화면에서 운행 시작과 위치 공유 동의를 직접 누르고 정확한 위치·알림 권한을 허용하면 `location` 유형의 포그라운드 서비스가 동작한다. 이는 휴대폰이 운행 작업을 인식하고 지속 알림을 보여주는 안드로이드 기능이다.
- GPS 수집·HTTPS 전송은 네이티브 서비스가 맡는다. 웹의 타이머·탭 유지·React 화면에 의존하지 않는다. 화면 해제는 서비스 종료 명령을 보내지 않는다.
- 화면 복귀 시 기기 상태를 읽어 운행 버튼과 마지막 서버 접수 시각을 복구한다. 앱에서는 웹 GPS를 실행하지 않는다.
- 정차 중에도 새 위치 표본을 받을 수 있도록 수신 거리 조건을 0으로 설정했다. 위치 콜백과 네이티브 타이머가 송신을 촉발하며 통신 구간의 CPU 유지에는 시간 제한을 둔다. 오래된 좌표를 망 복구 후 현재 위치로 재전송하지 않는다.
- 화면·지속 알림의 운행 종료로 기기 수집을 중단한다. 서버 종료 성공과 서버 종료 미확인을 구분하고, 미확인은 기기에 남겨 재시도한다. 새 운행으로 이전 종료 미확인을 덮지 않는다.
- 재부팅·강제 종료 후 몰래 위치 수집을 다시 켜지 않는다. 사용자가 앱에서 다시 시작해야 한다. OS 강제 종료·권한 철회·기기 절전·통신 장애까지 무중단으로 보장한다는 뜻은 아니다.

## 연결 보안과 서버

- 공식 HTTPS 출처와 `/driver/<token>` 최상위 화면만 기기 메시지를 사용할 수 있다. iframe·임의 출처·파일 접근·평문 HTTP·SSL 오류 무시는 허용하지 않는다. T맵·전화 링크는 허용한 방식으로 외부 앱을 연다.
- 운행의 비밀 인증값은 Android Keystore 기반 암호화 저장소에 보관하고 웹 화면에 전달하지 않는다. DB에는 비밀의 해시만 저장한다. 백업에서 자격 증명을 제외한다.
- `DriverMobileTrackingSession`에 12시간 유효한 운행 세션·기기 ID·전송 순서·측정 시각·서버 접수 시각을 저장한다. 시작 응답이 유실되면 같은 세션으로 재시도한다.
- 토큰별 트랜잭션 잠금과 활성 세션 고유 조건으로 다른 휴대폰의 동시 운행을 차단한다. 종료 후 들어온 옛 요청이 새 운행을 끄거나 되살리지 못하게 한다.
- 현재 정규 링크는 `ROLLING × REGULAR` 공용 링크 한 개다. 사용자가 **현재 1대 운행**이라고 확인했으므로 이번의 운행 링크당 한 기기 구조를 적용한다. 향후 여러 차량이 동시에 운행한다면 차량별 자격·링크·명단 범위를 먼저 분리해야 한다.
- 30초보다 오래되거나 5초보다 미래인 측정, 역순 전송, 종료·만료 세션은 위치를 덮어쓰지 못한다. 운행 링크가 삭제되면 기존 앱 자격으로도 전송할 수 없다.
- 기존 `DriverLocation`의 토큰별 최신 좌표 한 행을 재사용한다. 새 이동 경로 이력은 수집하지 않는다. 앱 세션이 소유한 링크는 세션 만료까지 웹의 지연 전송도 차단한다.
- 관리자 패널은 ‘마지막 서버 접수’라고 표시한다. 조회가 실패해도 경과 시간이 계속 증가하고 실패 경고를 보여준다. 오래된 좌표를 계속 실시간으로 보이게 하지 않는다.

SQL 준비 파일: `scripts/sql/driver-mobile-tracking-session.sql`. 공개 Data API 역할 권한을 제거하고 RLS를 켠다. **준비만 했으며 운영 DB에 적용하지 않았다.** 세션 만료는 기록 삭제가 아니다. 운영 활성화 전 세션 기록 보관·정리 기준을 확정해야 한다.

## 실기기 승인 기준과 출시 순서

다음은 **아직 통과한 결과가 아니라 실기기에서 확인할 시험 기준**이다.

1. 기사님과 같은 안드로이드 휴대폰에서 운행 시작, 화면 잠금 20분, T맵 전환 20분, 전화 수신을 포함한 운행 시험. 정상 수신 구간의 목표는 서버 접수 간격 30초 이내이며 위치 정확도와 배터리 사용량도 함께 기록한다.
2. 정차·절전·망 단절/복구·위치 권한 철회·알림 거부·앱 강제 종료를 시험한다. 끊김을 녹색 성공으로 표시하지 않고 복구 조작을 안내해야 한다.
3. 두 기기 동시 시작, 화면 재진입, 종료 직전 통신 끊김, 종료 후 옛 요청을 확인한다. 종료 후에는 새 좌표를 수집·전송하지 않아야 한다.
4. 승인된 시험 서버 또는 명시적 운영 시험 범위에서 실제 서버 접수 시각·측정 시각·관리자 표시를 대조한다. 모의 API 검사로 이를 대신하지 않는다.
5. 업턴랩스의 Play Console 계정·공개 게시자 정보·서명키·개인정보처리방침·위치 기능 고지·정확한 위치와 서비스 사용 신고·심사용 동작 자료를 준비한다. 실제 사용 방식에 필요한 위치 정책 심사를 확인한다.
6. 검증된 대상 버전과 SQL·활성화·배포·내부 시험/스토어 공개 범위를 제시하고 실행 직전 승인을 받아 반영한다. 시험용 APK를 그대로 정식 공개하지 않는다.

현재 Windows PC에서 물리 휴대폰 연결은 확인되지 않았다. 스토어 출시 계정은 **업턴랩스라는 주체만 확인했으며 계정 접근·등록 여부는 아직 확인하지 않았다.**

## 공식 근거

- [Android 위치 권한](https://developer.android.com/develop/sensors-and-location/location/permissions): 위치 유형 포그라운드 서비스를 실행하면 홈 화면 이동·화면 꺼짐에도 위치 접근을 이어갈 수 있다.
- [Android 위치 서비스 유형](https://developer.android.com/develop/background-work/services/fgs/service-types#location): 서비스 유형과 실행 전 권한을 요구한다.
- [사용자의 서비스 강제 중지](https://developer.android.com/develop/background-work/services/fgs/handle-user-stopping): 사용자가 실행 중인 서비스를 중지할 수 있다.
- [Google Play 서비스 신고](https://support.google.com/googleplay/android-developer/answer/13392821): 서비스 유형과 기능 사용 자료를 신고한다.
- [Google Play 위치 사용 정책](https://support.google.com/googleplay/android-developer/answer/9799150): 최소 권한·사용자 고지와 실제 사용 방식에 따른 심사를 확인한다.
- [Chrome 페이지 수명](https://developer.chrome.com/docs/web-platform/page-lifecycle-api): 숨겨진 웹 페이지는 정지·제거될 수 있다.
