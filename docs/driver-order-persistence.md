# 기사님 순서·시각 저장과 재조회 일치

2026-10-19. 사용자 승인으로 기존 UI 전용 범위를 저장·재조회 코드까지 확대했다. 운영 DB 변경·푸시·배포는 하지 않았다.

## 발견한 괴리와 수정

- 기존 API는 `RegularShuttleStop`만 변경하지만 확정 배차가 있으면 기사 화면은 `RegularDispatchRoute.payload`를 먼저 읽었다. 두 자료를 하나의 거래(모두 성공하거나 모두 취소되는 저장 묶음)로 갱신한다.
- 카드를 옮겨도 시각이 그대로면 재조회 시 시각순으로 원복됐다. 이동한 시각 칸을 표시·저장에도 함께 적용하며 직접 시간 입력도 즉시 정렬에 반영한다.
- 명단만 성공하거나 0건·미확인 응답이어도 완료로 처리하던 경로를 막았다. DB에서 명단과 확정 배차를 재조회한 뒤 `ok/verified/updated`가 모두 맞아야 편집을 종료하고 서버 자료를 갱신한다.
- 편집 시작 시 조회 원본을 고정한다. 서버는 원본의 정차 묶음·시각·순서가 현재 자료와 같은지 비교하여 오래된 화면의 덮어쓰기를 거절한다. 편집 중 새 서버 자료가 와도 원본 기준은 바뀌지 않으며, 저장 후 새 자료가 오면 이전 임시 편집값을 무시한다.

## 저장 범위와 보존 조건

정규 노선은 **날짜별이 아닌 적용 월·요일 공통**이다. 같은 달의 다른 월요일도 변경을 공유한다. 특정 날짜만 바꾸는 새 기능을 추가한 것은 아니다. 특강 저장·탑승 기록·운행 세션·위치 공유 계약은 유지한다.

서버는 유효한 날짜·정차 UUID·중복 없는 전체 묶음·연속 순서·HH:mm 또는 빈 시각을 검증한다. 기존 학생 연결 SQL과 실제 기사 명단 조립을 재사용한다. 학생 ID를 임의로 새 매칭하지 않는다. 연결되지 않거나 숨겨진 정차가 있어 화면과 전체 명단이 다르면 409로 취소한다.

명단과 노선 행을 일정 순서로 잠그고 Serializable 거래에서 변경한다. 확정 배차의 시각3필드와 학생 정차 슬롯만 변경하며 차량·회차 사이 이동은 거절한다. 차고지·경유지 슬롯, 좌표, 학생·차량 메타데이터는 보존한다. 확정 배차가 없는 기존 명단 경로도 유지한다. 추가 테이블·스키마 이관은 없다.
