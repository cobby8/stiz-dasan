# 운영 메인 화면의 첫 HTML 스타일 누락 수정

## 범위와 승인

사용자는 2026-10-25 운영 메인 화면이 기본 문서처럼 보이는 현상을 제보하고 스타일 누락 수정·검증을 승인했다. 운영 배포는 검증한 커밋과 영향을 제시한 뒤 실행 직전 확인한다. 제품 변경은 Home와 PublicSiteTheme 두 파일이며 조회·권한·데이터·설정은 바꾸지 않는다.

| 그룹 | 담당 | 의존 관계 | 완료 기준 |
|---|---|---|---|
| 원인·경계 조사 | 공개 스타일 explorer / PM | 운영 HTML·CSS와 사용처 대조 | 메인 누락·다른 경로/업무 화면 영향 구분 |
| 수정·회귀 | PM | 최소 두 파일안 승인 | null 주소에서 실제 Home 첫 HTML 스타일 포함, 기존 판단 유지 |
| 실행본 검증 | 독립 tester / PM 서버 단독 | 최종 소스·격리 빌드 | JS 비활성 최초 HTML·실제 CSS 화면·활성 후 수화·모바일/PC |

## 운영 재현과 원인

- 운영 커밋 `0238c357`의 Production 배포는 READY이고 운영 도메인에 연결돼 있었다. 그러나 배포 성공·HTTP200은 실제 디자인 적용을 보장하지 않았다.
- `https://www.stiz-dasan.kr/`의 공개 HTML에는 `.public-home-hero`와 헤더는 있지만 `stiz-public-sport` 클래스가0개였다. 연결된 CSS4개는 전부200이고 홈·공개 스포츠 선택자도 정상 포함돼 있었다.
- `/annual`, `/about`, `/login`의 공개 HTML에는 해당 클래스가 있었다. 메인의 공개 스타일 범위가 첫 HTML에서 빠지는 것이 직접적인 파손 원인이다. 사용자의 브라우저 캐시 문제로 단정하지 않는다.
- PublicSiteTheme가 브라우저 주소 판별에만 의존했다. 서버가 이미 홈을 공개 페이지로 알고 있어도 주소가 아직 없으면 스타일 표시가 빠질 수 있었다.

## 최소 수정

- PublicSiteTheme에 선택적 `publicScope`를 추가한다. 명시값이 있으면 그 값을 사용하고 없으면 기존 주소 판별을 유지한다.
- 홈 서버 페이지만 `publicScope={true}`를 전달해 첫 HTML부터 공개 스타일을 보장한다. 브라우저 주소 준비 전후에 같은 표시를 유지한다.
- 다른 호출부에는 값을 추가하지 않았다. 직원 로그인·설치 별칭(`/staff/login`, `/mypage/install`, `/staff/install`)의 기존 모양과 관리자·학부모·교사·기사님 업무 화면 경계를 보존한다. 전역 스타일 적용 범위를 늘리거나 CSS/데이터/권한을 바꾸지 않는다.

## 자동 검증

- 실제 Home·Theme 코드를 불러 순수 공개 조회 응답으로 서버 렌더링한다. 주소가 null이어도 최초 HTML의 루트에 클래스가 있는지 검사한다.
- 명시 true/false, 미지정 null, 업무 경로·별칭, 기존 공개 경로 유지 검사4건 추가. 기존 공개 범위2건과 합해6/6 통과했다.
- 전체 `npm test`: 회귀2471/2471·학생 보호5/5 통과. `tsc --noEmit`, 변경 Theme ESLint 오류0, diff 검사 통과.
- 실행본은 운영 연결·환경 파일·인증·서명키 복사 없이 기존 소유 로컬 합성 DB와 공개 자료를 사용한다. 최신 원격의 안전한 next.config/package/통합 manifest만 별도로 맞추고, source907개를 개별 해시로 복사한다. 운영 접수·로그인·발송·배포는 실행하지 않는다.
