# 터치 기기 입력 글씨와 아이폰 날짜·키보드 검증

기준: 2026-11-02, `codex/main-validation-20261101`. 운영 배포·TestFlight·새 원격 빌드 없이 승인된 공통 스타일과 로컬 회귀 검사를 보완했다.

## 최종 재확인: 임시 CSS 적용 실기기 통과

- 사용자 재확인 요청 후 USB 연결이 복구됐다. 사전에 사용자가 기존 확대를 수동으로 줄인 상태에서 같은 수정 CSS를 임시 적용한 iPhone 빌드5를 검사했다. 가로 750px, 입력 글씨 17px, visual scale 1, 페이지/요소 가로 넘침 0을 직접 계측했다.
- 가로 키보드 상태의 visual 높이는 82px였다. 최초에는 신청 버튼이 가려졌지만 추가 스크롤 후 버튼 전체가 회색 네이티브 보조 막대 위에 표시되는 PNG를 직접 확인했고 독립 검토도 일치했다. 항상 입력칸과 버튼이 동시에 보인다는 뜻은 아니며 실제 신청 버튼을 누르지 않았다.
- 이번 재검사 시작 시 날짜는 다시 선택된 상태였다. 지우기 버튼을 재실행해 빈 값·버튼 숨김·사유 ‘합성’ 2글자 유지·배율1을 확인했다. 전체 기간 내내 날짜가 비어 있었다고 기록하지 않는다.
- 키보드 닫힘 후 가로 750×354, 세로 복귀 후 402×750에서 빈 날짜·사유 유지·17px·배율1·가로 넘침0을 확인했다. 중간 blur 검사 연결 실패는 성공에서 제외하고 별도 재시도 성공으로 확인했다.
- 완료 후 임시 CSS 태그와 회전 관찰기를 제거했다. 정리 후에도 세로 402×750·빈 날짜·사유2·배율1을 확인했다. 설치 IPA·원래 서버 번들·운영 사이트에는 수정 사항을 반영하지 않았다.
- 판정: 로컬 수정·계산 스타일·임시 CSS 실기기 대조 통과. 기존 확대가 저절로 해제된다는 뜻은 아니며 새 시험 번들/서명 앱 반영과 검증은 별도다. 새 원격 빌드·설치·운영 배포·TestFlight 실행 없음.
- 추가 증거: `.tmp/ios-build5-install/date-recheck-{current,submit-scroll,cleared,blur-retry,portrait-final,cleanup}.json`, `date-recheck-{keyboard,submit-scroll,portrait-final}.png`. 실패 기록은 별도로 보존한다. JavaScript 콘솔은 수집하지 않았다.

## 완료한 실기기 검사

- 기존 검증 기록 250b6ad3·a12556bd를 검증 브랜치에 푸시했다. main과 자동 배포 차단 설정은 변경하지 않았다.
- 설치된 iPhone 빌드 5에서 복귀 날짜 선택·지우기 버튼 표시를 확인했다. 실제 버튼을 누른 뒤 날짜 값은 비고 버튼은 숨겨졌으며 사유 ‘합성’ 2글자는 유지됐다.
- 가로 전환 후와 세로 복귀 후에도 빈 날짜·사유 2글자가 유지됐다. 파일명보다 실제 계측 폭·높이로 방향을 판정했다.
- 세로 키보드에서는 사유칸과 신청 버튼이 실제 화면에 함께 보였다. 최초 사유가 비어 있던 캡처는 입력 보존 성공으로 계산하지 않고 재입력 후 측정했다.
- 전후 시험 서버의 차단·업로드·저장 카운터는 증가하지 않았다. 이 카운터는 전체 API 요청 수가 아니므로 ‘전체 요청 0’의 근거로 쓰지 않는다. 신청 버튼은 누르지 않았다.
- USB 장치는 보이지만 검사 연결이 0대로 되는 문제가 반복됐다. 사용자가 Apple Mobile Device Service를 재시작한 뒤 복구됐으며, 기기 미연결·로딩·검사 실패를 성공 집계에서 제외했다.

## 가로에서 발견한 문제와 수정

- 기존 CSS는 600px 이하에서만 입력 글씨를 보호했다. iPhone 가로에서 사유 글씨 14.875px·확대 1.076배가 함께 관측됐고, 키보드를 닫고 세로로 돌아와도 확대가 남았다. 작은 글씨와 확대의 관측은 정합적이지만 인과를 단정하지 않는다.
- 가로 스크롤 후 DOM 좌표가 visualViewport 안에 들어와도, PNG에서는 신청 버튼 일부가 네이티브 키보드 보조 막대에 가려졌다. 버튼 전체 접근 통과로 처리하지 않는다.
- `src/app/academy-theme.css`: 좁은 화면 또는 터치 입력 장치에서 학원 화면의 입력·선택·사유 글씨를 `max(1rem, 16px)`로 유지한다. 체크·라디오 및 학원 화면 밖 요소는 이 규칙의 대상에서 제외한다. 조회·신청 API와 저장 규칙은 바꾸지 않았다.

## 로컬 검증과 초기 실기기 보류 이력

- `node scripts/test-academy-touch-input-browser.mjs`: 실제 CSS 컴파일·계산 스타일 18/18 통과. 터치 폭 402/750/874/1024, 비터치 1440/402, 정상·큰 글씨 19px·작은 기본 글씨 조합을 확인했다. fixture 외부 요청 0, 사용자 브라우저·서버·기기 접속 없음.
- 독립 이전 CSS 비교 2/2: 터치 750px의 14.875→17px, 1024px의 14→16px. 큰 글씨·체크·라디오·범위 밖 글씨 보존을 확인했다.
- `npx tsc --noEmit` 통과. 기존 가족 UI 10/10·수강 변경 31/31 통과. 가족 UI 시험의 기존 모의 Link `prefetch=false` 경고는 오류와 구분한다.
- 같은 CSS만 현재 아이폰 WebView에 임시 style 태그로 적용했다. 설치 IPA·원래 시험 번들은 변경하지 않았다. 이미 생긴 확대는 임시 CSS 적용만으로 해제되지 않았다. 사용자 확대 원복·가로 재입력 완료 응답 뒤 USB 검사 연결이 다시 0대가 됐다. Apple 서비스 재시작 뒤에도 연결 0대를 재확인해 수정 후 가로 확대·보조 막대 가림의 실물 재검증을 보류했다. 사용자 응답만으로 해결 판정을 올리지 않았다. 당시에는 임시 태그 제거도 실행하지 못했으나 최종 재검사 후 정상 제거했다.
- 원본 CSS가 바뀌었으므로 기존 run0770의 source-hash는 최신 소스와 같지 않다. 옛 번들 검증 결과를 수정 반영 완료로 확대하지 않으며 가드를 낮춰 서버를 재실행하지 않았다. 기존 900초 시험 서버는 정상 만료 종료했다. 소스 변경 후 이 서버를 재시작하거나 원본 해시를 덮어쓰지 않았다.
- 로컬 스타일 계산만으로 iOS 결과를 대신하지 않는다. 상단의 임시 CSS 실기기 대조와 설치 앱 업데이트·출시 준비 완료를 구분한다. 새 시험 번들·서명 빌드·설치가 필요하면 별도 실행 승인을 따른다.
