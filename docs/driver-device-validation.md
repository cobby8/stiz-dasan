# 기사님 앱 실기기 검증

2026-10-19 · 업턴랩스 출시 준비 · USB 연결 태블릿 단기 시험 완료, 운영·출시 미적용

## 승인과 대상

- 사용자가 연결된 갤럭시 탭 S7+(SM-T975N)를 테스트 대상으로 확인했다. 단말 조작은 PM 한 명만 담당한다.
- Android 13(API 33), GPS·네트워크 위치 지원, 위치 설정 켜짐, T맵 설치를 읽기 확인했다. 테스트 앱 패키지는 기본 프로필에서 별도로 설치한다. 보호된 다른 프로필은 접근하지 않는다.
- 기존 앱·운영 DB·사이트·문자·알림은 변경하지 않는다. 테스트 앱은 별도 패키지이며 합성 운행·합성 학생만 표시한다.

## 데이터와 연결 경계

- 시험 서버는 PC의 loopback 주소만 사용하고 USB 연결을 통해 태블릿의 `https://localhost:8443`에서 접속한다. 운영 접속 정보는 사용하지 않는다.
- 시험 전용 CA의 공개 인증서만 debug 앱의 localhost 범위에 넣는다. SSL 오류 무시·평문 HTTP·기기 전체 인증서 설치를 사용하지 않는다. 개인키와 DB 자격은 임시 폴더에만 둔다.
- 실제 위치는 격리 DB의 최신 좌표 한 행으로만 받아 기능을 확인한다. Git·문서·JSON·일반 로그에는 좌표·세션 비밀·전체 기기 식별자를 기록하지 않는다. 시험 종료 후 소유한 DB·비밀 파일을 정리한다.
- 서버 상태 요약에는 수신 횟수·측정/접수 시각·간격·정확도·상태만 포함한다.

## 시험 순서와 해석

1. 앱 설치 → 실제 위치·알림 권한 흐름 → 운행 시작 → 최초 위치 접수.
2. 화면 잠금 상태에서 서버 접수가 계속 늘어나는지 확인.
3. T맵 전환 중 위치 접수·복귀 후 운행 상태 유지 확인.
4. 운행 종료 → 기기 수집 중단·서버 STOPPED → 추가 위치 전송 없음 확인.
5. 로컬 시험 서버·USB 전달 경로·정밀 위치가 남은 DB를 정리.

USB 충전 상태의 한 태블릿 시험이다. 배터리로 운행하는 기사 휴대폰·실제 도로 주행·통신사 전환·모든 제조사 절전·장시간 Doze 동작을 대신 증명하지 않는다. 실제 위치를 얻지 못하면 화면 밖 지속 전송도 통과로 표시하지 않는다.

## 현재 결과

수정 앱의 새 운행 시작과 정상 상태 표시, 화면 잠금 약3분 동안 위치10건 추가 접수, T맵 사용 약3분 동안18건 추가 접수를 확인했다. 모든 관찰 요약에서 요청 실패0건이었다. 사용자 앱 복귀·상태 유지·수동 종료 보고 후 서버 STOPPED·sharing=false와 마지막 접수 후55초 추가 수신0을 확인했다. 시험 서버·DB·임시 비밀 정리와 USB 전달 해제를 완료했다. 아래 설치/수정 내역은 당시 경과이며 최신 결과는 ‘수정본 실기기 확인’과 ‘최종 종료와 정리’를 기준으로 한다.

## 설치와 권한 복귀 수정 경과

기기 인식·OS·위치 설정·T맵·시간 차이(약 1초)를 확인했다. 별도 패키지 `kr.stiz.driver.devicetest`와 계측 앱을 기본 프로필에 설치했다. 최종 8443 빌드로 실제 단말의 URL 제한·KeyStore 계측 **13/13** 통과했다.

- 스트리밍 설치는 응답 확인에 실패해 후속 명령을 중단했다. 앱 미설치 상태를 확인한 뒤 `--no-streaming` 설치로 성공했다. 잠금은 사용자가 직접 해제했다.
- 기본 프로필만 조회하며 보호된 별도 프로필에는 접근하지 않았다.
- `adb reverse tcp:443`은 이 기기에서 권한 오류로 거부됐다. OS 권한을 바꾸지 않고 debug 기기 검증에서만 localhost:8443을 허용했다. 다른 host/일반 localhost:8443 거부 2건, release CA·설정 분리 14건, 시험 서버 정책 7건 통과.
- PC 임시 HTTPS 서버와 격리 PostgreSQL 실행 및 마스킹 상태 조회 성공. 최초 요약은 운행·위치 접수 0건이다.
- 자동 승인 검토가 태블릿에서 앱을 열고 UI 내용을 읽는 명령을 `blocked by policy`로 거절했다. 세부 이유는 제공되지 않았다. 같은 동작을 다른 도구로 우회하지 않고 화면 조작을 사용자에게 요청했다.

사용자가 최초 권한 허용 후 위치 상태가 보이지 않는다고 알려왔다. Android 13에서는 권한 결과가 화면 재개보다 먼저 전달되어 시작 요청이 버려질 수 있었다. 명시적 동의·같은 링크·2분 이내의 대기만 화면 복귀 후 한 번 이어가도록 수정했고, 권한 거절·서비스 실패 안내가 빈 초기 상태에 지워지지 않게 했다. 늦은 과거 상태도 실행 중인 서비스 상태를 덮지 않는다.

- 순수 Java 시작 정책 33개 조건, 독립 검증 9개 시나리오, 최종 소스 리뷰 통과.
- debug/test/release 빌드·Lint(오류 0·경고 4), TLS 격리 14건·잘못된 포트 거부 2건 재통과.
- 당시 권한 복귀 수정 앱 SHA256: `AEE3739B64953A8C93292E12B22042F0137A638116A146FADD58B049BA5CD588`. 별도 시험 앱을 재설치하고 실제 태블릿의 URL·KeyStore 계측 **13/13 재통과**. 이 계측은 위치 수집·서버 호출을 하지 않는다.
- PC 원본 화면을 시험 CA로 검증하여 제공되는 화면의 시작 버튼 표시를 확인했다. Android 화면이나 실제 위치 접수를 대신하는 증거는 아니다.

당시 수정 앱에서 사용자 수동 시작 후 한국시간 11:36~11:44에 운행 시작 1건·위치 26건·실패 0건의 실제 서버 접수를 확인했다. 위치 정확도는 약 100m로 표시되어 정밀한 정류장 판정까지 검증한 것은 아니다. 사용자는 화면의 ‘위치를 가져오지 못했습니다’ 문구를 보고했다. 서비스가 이미 보낸 fresh 표본을 다시 보내지 않고 기다리는 상황도 오류로 처리하는 경로를 확인하여, 사용자 승인 후 정상 대기·위치 갱신 지연·전송 실패를 구분하도록 아래 후속 수정을 완료했다.

이 시점에는 첫 서버 접수만 확인한 상태였고, 후속 앱 재설치 전 사용자 수동 운행 종료와 서버 STOPPED 확인을 요청했다. 이후 단기 잠금·T맵 결과는 아래에 별도로 기록했다.

## 위치 대기·지연 안내 후속 수정

- 같은 fresh 표본은 재전송하지 않고 기존 상태를 유지한다. 최초 표본 대기는 25초까지 중립 안내, 이후와 오래된/미래 표본은 갱신 지연으로 표시한다. 대기나 지연이 직전 전송 실패를 지우지 않는다.
- 화면은 기기의 구체적 원인을 우선하며 마지막 실제 접수 시각·정확도를 오류 중에도 보여준다. 새 서버 응답 없이 성공이나 현재 위치로 꾸미지 않는다. 웹 권한·재시도·제약 안내는 유지한다.
- 자체 Java 위치 정책13·기존 권한33, 독립 Java14경계, 독립 실제 React Chrome10·bridge/hook통합 Chrome8·SSR8, 관련 회귀45, PM 회귀29 통과. TypeScript·관련 ESLint·diff 검사 통과.
- 앱 debug/test/release 빌드·Lint(오류0/기존경고4)·TLS격리14 통과. 새 APK SHA256 `DBF1F10DEA427377A2D59F2C88E9BFEE0D63CB543D90A22384E6786CA131BE0E`.
- 실행 중인 시험 서버는 인증서·API·DB를 유지하고 원본 UI 번들만 갱신했다. 정상 CA 검증을 거친 PC 화면 제공 검사 통과. 브라우저 상태 검사는 최종 제품 전체 시각 검증이나 Android 실제 서비스 검증을 대신하지 않는다.
- 사용자가 수동 종료 후 한국시간 11:51~11:52 서버 STOPPED·활성0·sharing=false·stop1을 확인했다. 마지막 위치48건 접수 후 39초 동안 추가 위치가 없었다.
- 검증된 새 APK를 같은 시험 패키지로 재설치하고 실제 태블릿 URL·KeyStore 계측13/13 재통과했다. 새 앱의 사용자 수동 운행 시작·상태 문구 확인을 요청했다. 이전 앱의 실제 접수 성공을 새 앱의 실기기 검증으로 옮겨 적지 않는다. 운영 반영·푸시·배포 없음.

## 종료 후 재시작 경로

사용자가 앱 재실행 후에도 ‘운행이 종료되었습니다’ 화면에서 새 운행을 시작할 수 없다고 보고했다. ended 복원 상태에 시작 버튼이 없는 경로를 확인하여 사용자 승인 후 헤더에 ‘다시 운행 시작’을 추가했다. 서버 종료 미확인에서는 ‘종료 재확인’만 제공하고 기존 stop 재시도로 연결한다. 화면 재진입만으로 시작하거나 서버 확인 없이 종료 완료로 표시하지 않는다.

웹 화면만 수정했으며 앱 APK·기기 권한·인증서·서버 API·DB는 바꾸지 않았다. PC 시험 화면 번들을 갱신하고 정상 CA 검증을 통한 제공 화면 검사를 통과했다. 이후 사용자 태블릿에서 버튼 확인과 수동 새 운행 접수가 이루어졌으며 아래에 기록했다.

독립 검사: 실제 native bridge/hook/React Chrome10·웹 기사 화면 Chrome10·GPS/운행 회귀38·TypeScript·변경 파일 ESLint·diff 검사 통과. PM 관련 회귀15 통과. 종료 snapshot 첫 진입/새로고침에서 자동 시작 없음, 수동 시작 요청 후 상태 전환, stop-unknown에서 시작 버튼 차단·종료 재확인·확인 중 비활성·실제 stopped 이후 재시작 허용을 확인했다. 초기 추가 테스트의 제목 선택자는 아이콘이 포함된 실제 문구에 맞게 고친 후 전부 재실행했다.

- 이 시험에서 만든 USB 전달tcp8443만 해제했다. 다른 프로젝트 서버·기기 프로필·앱을 변경하지 않았다. 시험 앱은 설치된 채 운행 종료 상태이며, PC 시험 서버 종료로 localhost 시험 링크는 더 이상 연결되지 않는다.
- 실제 설치된 앱은 debug 시험 패키지이며 운영 배포·Google Play 업로드·정식 서명을 하지 않았다. 운영 SQL/env도 미적용이다. 이번 단기 시험을 근거로 출시 완료로 표시하지 않는다.
