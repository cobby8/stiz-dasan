# 운영 문구·미사용 코드·셔틀 배차 정리

2026-10-20. 사용자가 세 변경 묶음을 승인했다. 로컬 구현·검증 작업이며 운영 데이터 변경·실제 발송·배포는 포함하지 않는다.

## 그룹과 소유 범위

| 그룹 | 담당 | 의존 관계 | 완료 기준 |
|---|---|---|---|
| 화면 문구·표시 함수 | UI 담당 | 전수조사 결과 | 중복 설명·개발 용어 정리, 필수 안내 보존, 표시 결과 유지 |
| 미사용 부품 | PM | 참조·진입점 확인 | 승인된 5개만 제거, 기존 페이지·호환 주소 유지 |
| 내부 오류 안내 | 서버 담당 | 업무 오류 분류 | 예상된 입력·권한 안내 유지, 내부 원문 노출 차단 |
| 배차 저장·조회 | 배차 담당 | 범위·저장 계약 | 늦은 응답 차단, 저장 후 확인, 시즌 격리, 상단·편집 결과 일치 |
| 통합 검증 | PM·독립 QA | 위 구현 완료 | 전체 검사·생산 빌드·합성 화면/DB 검증 후 결과 기록 |

## 조사 범위와 경계

- 화면: TSX 349개와 페이지 117개의 정적 문자열·실제 표시 경로를 조사했다. 주석·서버 로그·변수 이름을 화면 문구로 세지 않았다.
- 코드: 소스 862개 중 코드 파일 855개의 정적 import, 재내보내기, 문자열 기반 동적 import/require와 참조를 조사했다. Next.js의 파일명 기반 진입점과 기존 검사·운영 도구의 소비 여부를 구분했다.
- 운영 배포 기준은 `dbe3ff86`, 조사 시작 코드 기준은 `39baa603`이다. 운영과 미배포 변경을 구분했다.
- DB에 저장된 공지·FAQ·설정 문구는 이 소스 검사에 포함하지 않았다. 조회 과정에 자동 쓰기가 있는 운영 화면을 검사 목적으로 열지 않았다.
- 문자·푸시·카카오 발송 템플릿과 실제 발송, 결제 승인·청구, 자녀 등록은 변경하지 않는다.

## 문구 정리 기준

- 제목과 버튼을 반복하는 소개 문장을 제거하고 해당 문장만 차지하던 공간도 없앤다.
- `DB`, `migration`, `payload`, 내부 역할·처리 코드를 실제 업무 표현으로 바꾼다.
- 저장·반영·발송을 같은 의미로 쓰지 않는다. 조회 실패·입력 보존·권한·개인정보·위치 지연/전송 실패/공유 종료 미확인 고지는 유지한다.
- 정규 사전 결석은 기사 화면에서 결석 표시와 탑승 체크 제외로 반영된다. 월·요일 반복 노선의 정류장을 자동 삭제한다는 과장과 ‘다음 단계 연동’이라는 오래된 설명을 함께 정리한다.
- 글씨·기사 버튼 크기와 라벤더 스타일은 유지한다.

## 배차에서 확인한 문제

1. 월/요일 전환 뒤 이전 조회 응답이 현재 노선을 덮을 수 있었다.
2. HTTP 성공 상태만으로 저장 완료를 표시하고 응답 내용이나 저장 후 조회를 확인하지 않았다.
3. 특강의 같은 요일 대표일을 시즌 범위 없이 찾아 과거 시즌 날짜로 저장할 수 있었다. 삭제는 조회·저장과 다른 날짜 기준이었다.
4. 정규 상단 시간표와 상세 편집기가 서로 다른 노선 자료를 표시했다.
5. 최초 진입 시 저장본 여부·저장 시각이 유실됐다.
6. 저장본 조회 실패를 ‘저장본 없음’으로 취급해 자동 제안을 생성했다.
7. 예약된 재경로 계산과 응답에도 현재 범위 검사가 부족했다.

1~3은 원본 함수를 추출한 격리 실행과 가짜 응답으로 재현했다. 나머지는 조사 당시 소스 경로로 확인했으며, 실제 DB·화면 검증은 수정 후 별도로 기록한다. 이전 기사 순서·시간 저장 보완과는 다른 관리자 배차 경로다.

기존 정규 월×요일 공유, 특강 시즌×요일 공유, 정원 초과 시 확인, 학생·탑승 식별자 정책은 유지한다.

## 검증 상태

- G1 독립 검증: 관련 단위 59/59, 기사 상태 브라우저 10/10, 저장·전달 상태 브라우저 18/18 통과. 24개 TSX의 이벤트·접근성·조회/권한/GPS 호출은 원본과 동일하며 새 스타일·클래스를 추가하지 않았다.
- G2 독립 검증: 오류 안내 함수·응답 44/44, 추가 계정 연결 API 5/5, 기존 계정 연결 9/9 통과. 관련 기존 검사 118건도 구현 담당이 통과했다. 내부 업무 안내 98개는 정확히 일치하는 경우만 유지하고 날짜·건수는 제한된 형식만 허용한다.
- G3 독립 검증: 배차 검토 담당이 실제 함수/API 30/30, 관련 회귀 97/97, 별도 소유 시험 PostgreSQL 55482에서 26/26을 실행했다. 최종 월 선택 보완은 통합 QA가 함수/API 33건으로 확인했다. 시험 DB는 종료했다.
- 검토 중 장부 버전을 수정 횟수로 잘못 표현한 곳과 중복 원생 ‘의심’을 확정처럼 표현한 곳을 바로잡았다. 숨긴 위치 상세를 열지 않고 검사하던 브라우저 도구도 실제 조작 순서로 수정한 후 통과했다.
- 전체 회귀 첫 실행의 네 기대값/가드 문제를 수정하고 새 격리 사본에서 최종 전체 검사를 다시 실행했다. 278개 파일 2,193/2,193, 학생 보호 검사 5/5, 배차 함수/API 검사 33/33 통과했다. 실패·생략 0이며 소스·검사·설정 1,299개 해시는 복사 및 실행 전후 모두 일치했다. 증거는 `.tmp/qa-followup/cleanup-integration-final/`이다.
- 월을 바꿀 때 이전 요일이 새 달에 없으면 새 달의 유효한 요일을 즉시 표시한다. 공통 KST 날짜 함수를 재사용했으며 기존 날짜 보호 검사에 예외를 추가하지 않았다.
- 현재 관리 화면은 이전 저장 시각을 항상 보내고 서버가 비교한다. 기존 내부 호출은 선택적 인자 계약을 유지한다. 과거의 모든 호출 경로까지 새 계약을 강제했다고 주장하지 않는다.

### 별도 빌드 확인 사항

- 첫 격리 생산 빌드는 코드 컴파일·TypeScript를 통과했으나 `/opengraph-image` 정적 생성에서 실패했다. 실패한 시험 서버/DB는 종료·정리했다.
- 직접 의존 `sharp` 0.35.3과 Next.js 내부 0.34.5를 같은 프로세스에서 로딩하는 순서를 달리해 원인을 분리했다. 0.34.5 단독은 같은 공식 PNG를 처리하지만, 0.35.3을 먼저 로딩한 뒤 0.34.5가 처리하면 `colourspace: parameter space not set`이 재현된다. 원본 공유 이미지·사진 처리 코드는 이 조사 전부터 존재했다.
- 원본 `package.json`·잠금 파일·설치된 라이브러리는 변경하지 않았다. 0.34.5로 맞추는 안은 추가 승인을 요청하고 별도 복사본에서 검증한다. 후보 복사본 빌드를 원본 의존성의 생산 빌드 통과로 보고하지 않는다.
- 후보 복사본의 실제 UI/API 화면 검증 결과는 아직 없다. 통합 단위 검사와 분리해 추후 갱신한다.
- 최종 배포와 운영 결제 준비는 기존 배포 검증 기록의 별도 보류 상태를 유지한다.
