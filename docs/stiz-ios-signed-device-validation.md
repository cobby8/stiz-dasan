# STIZ 등록 아이폰 격리 서명 시험

## 후속: USB 설치와 시험 연결 보완
- 사용자가 공개 CA 설치·전체 신뢰를 완료했다. Safari OTA에서 ‘설치할 수 없음 / 나중에 다시 시도하십시오’가 나왔고, 당시 전달 경로 13검사·IPA 서명·프로파일 재검사에는 오류가 없었다. OTA 실패의 구체 원인은 미확정이다.
- 공식 npm Appium iOS 도구를 `.tmp` 전용 경로에 준비해 기존 Apple USB 연결을 사용했다. 현재 기기와 IPA의 단일 등록 기기를 메모리에서 일치 확인하고, 승인된 같은 IPA를 USB 설치했다.
- 설치 후 STIZ 앱 하나만 조회해 `0.1.0 / 빌드 1`을 확인했으며 독립 재조회도 통과했다. 다른 앱·개인 자료·원본 기기 로그는 수집하지 않았다.
- 사용자 실행 결과는 빈 화면·다시 불러오기다. STIZ 앱만 선택한 읽기 전용 WebInspector에서도 페이지 1개가 빈 상태임을 확인했다. Safari의 같은 시험 주소는 사용자가 ‘네트워크 연결 유실’로 보고했다. 설치 성공과 화면 실행 성공을 구분한다.
- 첫 포트 필터 조회를 서버 종료로 잘못 판단했으나 철회했다. 기존 서버 PID와 시작 시각이 유지됐고 엄격한 TLS 상태 조회가 200이었다. 서버 재시작은 하지 않았다.
- Apple 문서의 iOS 17 이후 숫자 IP 접속 설정을 확인해, 사용자가 시험 앱 한정 수정·검증 브랜치 푸시·재서명·같은 아이폰 재설치를 승인했다.
- 생성 SandboxInfo에만 정확한 시험 IP 한 개를 명시하고 HTTP 차단·TLS 1.2 이상·순방향 안전성·인증서 검증을 유지한다. 원본 Info·Release·운영 설정은 바꾸지 않는다.
- 시험 Debug의 유효한 격리 주소에서만 고정 안내와 제한된 오류 코드가 표시된다. URL·원문 예외·사용자 정보는 표시하거나 기록하지 않는다.
- 독립 Python 9건·프로젝트 28건·Node 22건, 전체 회귀 2,590건 및 학생 표시 보호 5건 통과. `0192ea280425f0bf23c1b148f42df5b5b900b5dd` 검증 브랜치 푸시 완료.
- 서명 #2 `6ae1920b206ce93970c6bc2e`, 실제 `0192ea2`, M2·SSH 끔·15:11 KST 시작 후 `finished` 1분10초. 새 IPA 116,243바이트를 정상 다운로드했다.
- IPA SHA-256 `30048c7ea8ba9eb4670fe5094507700c7e507dea26e497b3fded0e968201e011`이 Mac 보고서와 일치한다. 독립 검사에서 정확한 ATS 설정·버전2·프로파일·실행파일 CMS·코드 페이지20·특수 슬롯5·봉인 자원2와 ZIP 경계를 재검증했다.
- 기존 앱이 `0.1.0/1`인 경우만 허용하는 조건으로, 현재 USB 기기와 새 프로파일 단일 기기를 메모리 대조한 뒤 같은 앱을 업데이트했다. 설치 후 STIZ만 조회해 `0.1.0/2`를 확인했고 독립 재조회도 통과했다.
- 사용자는 빌드2 실행·완전 종료 후 재실행에서도 버튼만 보이고 안내 글자는 없으며 라이트 모드라고 보고했다. 새 IPA에는 색상 자산과 진단 문구가 실제 포함돼 있다. 현재 화면 실행은 여전히 실패 상태이며, 실제 화면 자료로 표시 문제와 연결 문제를 추가 구분해야 한다.
- STIZ 관련 설치·통신 오류만 즉시 메모리 필터한 짧은 USB 관찰에서는 원인을 확정할 숫자 코드를 얻지 못했다. 원본 기기 로그는 저장하지 않았다. 다크 모드 대비 문제는 잠재 사항이지만 현재 원인으로 단정하거나 추가 수정하지 않았다.
- 운영 배포·TestFlight·운영 데이터·결제·발송은 변경하지 않았다.
- 근거: [Apple IP 주소 접속 설정](https://developer.apple.com/documentation/bundleresources/information-property-list/nsapptransportsecurity/nsallowslocalnetworking), [정확한 주소별 설정](https://developer.apple.com/documentation/bundleresources/information-property-list/nsapptransportsecurity/nsexceptiondomains).

## 검증 구성
- 수동 워크플로 `stiz-ios-sandbox-adhoc`: Debug·실제 아이폰용 서명, `https://172.30.1.12:8453`만 허용.
- 등록 기기 한 대·STIZ 앱·조직·Ad Hoc 권한·인증서 일치와 IPA 서명을 빌드 전후 검사한다.
- 스토어 배포 단계는 없으며 IPA와 개인정보 없는 검증 JSON만 보관한다.
- 원격 오류는 단계·명령 이름·종료 번호만 표시하고 원문 프로파일·기기 식별자·환경을 출력하지 않는다.
- WebInspector는 유효한 격리 주소가 있는 Debug 앱에서만 활성화한다. 일반 앱에는 적용하지 않는다.

## 설치 준비
- 기기 설치는 정상 서명·등록 프로파일을 사용한다. iOS의 인증서 검증·앱 주소 차단은 유지한다.
- 격리 서버 공개 CA만 사용자에게 전달하고, OS 신뢰 설정은 사용자가 직접 수행한다. 개인 키는 전달하지 않는다.
- Python 도구는 기존 Python 3.14 절대 경로와 전용 격리 환경을 사용한다. 시스템 별칭의 자동 설치를 사용하지 않는다.
- 잘못된 별칭 호출로 저장소 아래 생성된 임시 Python 폴더는 `.tmp`로 격리했으며 실행하거나 Git에 포함하지 않았다. 기존 Python은 유지했다.

## 사용자 기기 조작 대기
- HTTPS 설치 서버를 기존 시험 서버와 분리하고 비공개 경로의 설명 페이지·manifest·같은 IPA만 제공한다. 접근 로그·외부 전송·다른 파일 제공 없이 30분 후 종료한다.
- 등록 아이폰 사용자가 시험 공개 CA 설치·신뢰 후 로컬 설치 QR을 열어야 한다. OS 신뢰 설정과 설치 확인을 자동으로 건너뛰지 않는다.
- QR과 비공개 설치 경로는 이 PC의 `.tmp/stiz-ios-device-install/ota/`에만 보관하며 Git·Issue·공개 문서에 넣지 않는다.
- 설치 전달 경로 독립 검사 13조건 통과: 정확한 3경로·GET/HEAD만 허용, 다른 경로·POST 차단, TLS CA/IP 검증과 미신뢰 CA 거부, manifest 앱 정보·전송 IPA 해시 일치. 기기 설치·WebKit 실행은 사용자 조작 후 별도 확인한다.
