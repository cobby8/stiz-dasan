### 실제 CSV 내보내기의 후속 범위

- 읽기 조사만 했다. 특강 내보내기는 현재 필터의 합성 자료가 아닌 운영 조회를 실제 실행하지 않고 소스만 대조했다. 실제 흐름은 페이지별 명단 조회 후 UTF-8 BOM/CRLF·공유 CSV 셀/파일명 방어·보호자 마스킹을 거쳐 Blob/anchor.click/즉시 revoke다.
- 셔틀 내보내기는 현재 검색된 탑승 행을 메모리에서 BOM/LF/quote escape로 만들고 Blob/anchor.click/즉시 revoke한다. 이 경로는 전화 열의 별도 마스킹이나 공유 수식 prefix 방어를 사용하지 않는 기존 차이가 있다. 실제 연락처·명단·CSV는 생성하거나 수집하지 않았다.
- 두 흐름의 Blob URL은 현재 HTTPS 다운로드 정책에서 계속 거부된다. 비동기 Blob 인계는 즉시 revoke 수명과 사용자 시작 판정도 설계해야 한다. 글로벌 blob/data 허용으로 우회하지 않고, 두 내보내기만의 인증된 파일 응답 또는 엄격한 같은 origin CSV 인계를 별도 승인 그룹으로 설계한다. 기존 열·필터·마스킹 정책을 수단 변경에 몰래 섞지 않는다.
