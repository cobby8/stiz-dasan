# STIZ Codex 운영 PC 설정 및 인수인계

## 목적

학원 PC를 STIZ 운영 실행기로 준비하고, 다른 PC의 Codex와 같은 규칙·지식·스킬을 사용하게 만드는 표준서다. 문서를 읽는 것만으로 운영 DB 변경, 배포, 청구, 결제, 삭제 또는 외부 발송이 승인되지는 않는다.

## 단일 실행기 원칙

운영 실행기는 시트·Rallyz·사이트 쓰기와 예약 대조를 수행하는 유일한 PC 또는 세션이다. 나머지 PC는 기본적으로 조회와 dry-run만 수행한다.

인계 순서는 다음과 같다.

1. 기존 실행기의 예약작업을 `PAUSED`로 전환한다.
2. 마지막 실행 결과와 `PENDING`, `HELD`, `PARTIAL` 원장을 기록한다.
3. 새 실행기에서 세 시스템을 읽기 전용으로 확인한다.
4. 새 실행기만 `ACTIVE`로 전환한다.
5. 첫 실행 결과에서 중복 발송·중복 청구·누락이 없는지 확인한다.

앱 수준 실행 잠금이 구현되기 전까지 이 운영 원칙 자체가 중복 방지 장치다. 실행기 고유 ID, 활성화 시각, 이전 실행기 중지 확인이 하나라도 비어 있으면 새 PC는 `PAUSED`로 유지한다. 기존 PC에 접근할 수 없다면 새 PC의 무인 외부 쓰기도 활성화하지 않는다.

## 학원 PC 준비

- Windows 시간대와 시각이 `Asia/Seoul` 기준으로 맞는지 확인한다.
- Codex에 동일한 운영 계정으로 로그인한다.
- 저장소를 `C:\0.programing\stiz-academy-A`에 준비하고 `main` 브랜치와 기준 커밋을 확인한다.
- Node.js와 npm은 저장소의 lockfile 및 실제 검사 결과와 호환되는 버전을 사용한다.
- 운영용 Chrome 프로필은 개인 브라우징과 분리하고 화면 잠금을 사용한다.
- 개발서버 종료 시 전체 `node.exe`를 종료하지 않고 포트의 PID만 종료한다.

## 저장소 준비

```powershell
git status --short
git branch --show-current
git pull
npm ci
npx.cmd prisma generate
npm run release:code-check
npm run release:preflight
```

`release:code-check`는 코드 중심 검사이고, 운영 준비 완료 판단에는 환경과 DB를 포함하는 `release:preflight`까지 통과해야 한다. 실패한 검사를 우회해 실행기를 활성화하지 않는다.

## 각 PC에 따로 연결할 항목

값 자체가 아니라 설정 여부와 마지막 검증일만 기록한다.

- Google Sheets API 활성화
- Google 서비스 계정과 대상 운영 시트 편집 권한
- Rallyz 로그인 및 `스티즈농구교실 다산2호점` 선택
- `stiz-dasan.kr` 관리자 로그인
- 운영 DB 및 Vercel 환경 구분
- 문자·결제 공급자 설정 여부
- Codex 브라우저 제어 연결

`.env.local`, 서비스 계정 private key, DB URL, API 키, 쿠키와 세션은 Git에 넣지 않는다.

## 최초 읽기 전용 검증

1. 사이트 관리자 화면과 학생 상세를 읽는다.
2. 시트 `등록`과 현재 월 차량 탭을 읽는다.
3. Rallyz 학생·수강·청구·출석을 읽고 정확한 학원명이 선택됐는지 확인한다.
4. 한 학생을 골라 이름뿐 아니라 안정 ID, 생년월일, 보호자 연락처 끝 4자리, 반, 적용 월을 대조한다.
5. 쓰기나 발송 없이 dry-run 원장을 작성한다.
6. 세 시스템의 예상 상태가 같아야 실행기 활성화 후보가 된다.

## 예약작업

- 매일 오전 10시 대조 예약은 한 실행기에서만 `ACTIVE`로 둔다.
- 기존 automation을 갱신하고 같은 목적의 새 예약을 중복 생성하지 않는다.
- 월 청구 검증은 공식 연간일정표의 다음 개강일 정확히 14일 전일 때만 실행한다.
- 청구 발행·취소·결제·환불·문자·알림·학부모 초대는 실행 직전 미리보기 승인이 필요하다.
- Rallyz 사용 종료가 확정되면 Rallyz 단계와 관련 청구 예약을 중지하고 인수인계에 기록한다.

## 운영 순서

안정 식별 → 적용일과 변경 종류 → dry-run → 모호 항목 `HELD` → 정확한 미리보기 승인 → 시트 → Rallyz → 사이트 → 세 시스템 재조회 순서로 처리한다.

Rallyz 쓰기는 공식 API가 확인되지 않은 로그인 브라우저 감독형 단계다. 버튼을 눌렀다는 사실이 아니라 결과 화면을 다시 읽어 성공을 확인한다.

## 장애와 복구

- 로그인 만료, 시트 권한 오류, DB 검사 실패는 `PARTIAL`로 기록하고 추측 적용하지 않는다.
- 중단 후에는 이미 성공한 대상을 건너뛰고 `PENDING` 또는 `FAILED` 대상만 재조회한 뒤 재시도한다.
- PC 분실이나 교체 시 예약을 먼저 멈추고 세션을 폐기하며 필요한 secret을 교체한다.
- 긴급 중지는 예약과 외부 발송 실행을 멈추는 것이며 감사 원장을 삭제하지 않는다.
