# Decisions

## 2026-10-22 공개 일정·모집·메뉴 후속 기준
- 특강 날짜는 KST 한국어 날짜로 표시한다. 서버의 종료/마감/취소를 시간 계산으로 다시 열지 않으며, 잘못된 일정과 모르는 좌석 수는 임의로 추정하지 않는다. 기간과 실제 수업 상태를 배지·설명·신청 버튼에 일치시킨다.
- 연간 일정은 1~12월 가로 선택과 하나의 열린 월 패널로 구성한다. 첫 진입은 한국 현재 월, 다른 월 열람은 유지하고 ‘이번 달’로 복귀한다. 회전해도 선택 월을 띠 안에 유지한다. 공식 수강월/수업일과 기존 새로고침은 보존한다.
- 공개 헤더는 768px 이상 메뉴를 보이며 좁은 PC·태블릿·큰 글씨에서는 별도 줄로 배치한다. 휴대폰은 ‘메뉴’ 글자가 있는 서랍으로 제공한다. 기존 메뉴/링크/업무 화면과 API·데이터 조회는 변경하지 않는다.

## 2026-10-21 공개 홈페이지 스포츠 스타일 범위
- 사용자가 강한 스포츠 컨셉을 선택해 실제 공개 UI에 적용한다. 메뉴·자료 조회·신청 검증·계산·권한은 유지하고, 업무용 라벤더 화면에는 공개 CSS를 적용하지 않는다.
- 공개 화면은 `PublicSiteTheme`/경로 판별로 감싸며 색상은 `.stiz-public-sport` 내부 변수로 제한한다. 공개 테마 기본값은 라이트, 저장 키는 `stiz-public-theme`로 분리한다. 기존 업무 화면의 테마 규칙을 유지한다.
- 운영 DB에 개발 앱을 연결하지 않는다. 공개 캡처를 합성 QA DB로 재구성한 최신 소스 복사본에서 생산 빌드·좁은 화면을 확인하며, 실제 접수/계정/발송/결제와 배포는 차단한다. 전체 운영 데이터 복원본이나 실물 휴대폰 검증으로 표현하지 않는다.
- 상세 범위와 검증 증거는 `docs/public-sport-homepage.md`에 기록한다.

- 통합20·기존 화면19·회귀87·tsc·lint 통과. 실제 토큰/쿠키/세션/Supabase SDK·Next HTTP/middleware/layout·전체 Prisma 스키마는 다음 별도 인증 환경 검증으로 남긴다. 운영 활성화·배포는 별도 승인이다.

## 2026-09-04: 월 장부 이탈 보호는 미저장과 결과 미확인을 구분

- 히스토리 조작이나 라우터 전역 덮어쓰기는 도입하지 않는다. 동일 문서 뒤로가기·프로그램 이동·모바일 강제 종료 등은 별도 한계로 명시한다. 격리 브라우저19·회귀90 통과, 운영 배포는 미수행.

## 2026-09-04: 월 장부 실제 DB 검증은 격리된 로컬 클러스터로 수행

### 확정된 운영 규칙 4가지 (사용자 승인, 2026-07-25)
1. **보강 날짜가 그 학생의 원래 수업일과 겹치면 막는다.** ("그 날은 원래 수업이 있는 날입니다") — UI 후보 목록뿐 아니라 저장 경로(`createMakeup`)에서도 검사한다. 관리자·학부모 두 경로가 같은 함수를 타므로 한 곳만 막으면 양쪽이 막힌다.
2. **반 이동 시 예전 반 예정일은 자동 정리(소프트 취소)하되, 출결 찍힌 날은 보존한다.** 완전 삭제 금지.
3. **출결 찍힌 학생의 반 이동은 허용한다.** 막지 않는다. 다만 출결이 찍힌 날은 예전 반에 그대로 남고, 그 건수를 감사로그(`ITEM_ASSIGNMENT_UPDATED`의 `enrollmentDatesResync.blockedByAttendance`)에 남긴다.

## 2026-07-26: 방학특강 형제할인 10% — 확정 정책 8가지

- **① 형제 판정 = 보호자 전화번호 겹침.** 한 학생의 번호 집합은 `신청서 parentPhone ∪ 매칭 원생의 User.phone ∪ 그 학생의 모든 Guardian.phone`(숫자만 정규화)이고, 하나라도 겹치면 형제다. 합집합이어야 하는 이유는 아빠 번호는 신청서에, 엄마 번호는 원생 보호자에 등록된 사례(송서준)가 실재하기 때문이다.
- **② 할인 대상은 "같은 시즌을 같이 신청한 형제"뿐이다.** 형제가 정규반만 다니는 경우는 대상이 아니다. 판정 단위는 원생이 아니라 **시즌 내 신청서**다.
- **③ 형제 전원 각각 10%** (둘째부터가 아니다).
- **④ 기존회원가에서 또 10%** 중복 적용한다. 기존회원 주2회 150,000 → 135,000.
- **⑤ 수강료만 할인하고 셔틀비는 절대 할인하지 않는다.** 최종금액 = 수강료 − 할인 + 셔틀비.
- **⑥ 반올림은 `Math.floor`(원 단위 절사).** JS는 `Math.floor(tuition * 10 / 100)`, SQL은 `(tuition * 10) / 100` 정수 나눗셈으로 계산해 두 결과가 구조적으로 어긋날 수 없게 했다.
- **⑦ 중복 등록 의심 학생은 할인에서 제외한다.** 판정 기준은 **"이름 앞부분 동일 + 생일 차이 2일 이내"를 모두 만족**할 때만이다. 생일만으로 판단하면 진짜 쌍둥이(장승리/장하리, 이윤건/이윤서, 김루나/김루희)가 할인을 잃는다.
- **⑧ 번호가 잘못 등록된 2쌍(이시윤/최현, 남건희/박하진)은 형제가 아니다.** 이름이 아니라 **"문제의 전화번호 + 두 이름"** 조합으로 예외를 둔다(`MISREGISTERED_PHONE_EXCEPTIONS`). 두 사람을 잇는 공유 번호가 **전부** 예외로 설명될 때만 연결을 끊으므로, 같은 번호를 쓰는 진짜 형제가 나중에 생겨도 영향이 없고 원생 번호가 교정되면 규칙은 저절로 무의미해진다.
